## 设计

### `pkg/driver/endpoint.go`
```go
// ParseEndpoint 解析 --endpoint。支持 unix://<绝对或相对路径> 与 tcp://<host:port>。
// 返回 net.Listen 用的 network（"unix"/"tcp"）和 address。
func ParseEndpoint(endpoint string) (network, address string, err error)
```
- 前缀大小写敏感；地址为空或全空白 → 错误。
- tcp 地址必须能被 `net.SplitHostPort` 解析，端口为 0–65535 的数字（`0` 允许，测试用）。
- `cmd/glusterfs-csi` 的 `validateFlags` 改为调用它，删除 main.go 里重复的前缀判断逻辑。

### `pkg/driver/identity.go`
- `GetPluginInfo`：返回 `name=DriverName`、`vendor_version=Version`；不返回 manifest。
- `GetPluginCapabilities`：**能力由实际注册的服务推导**——只有注册了 Controller 服务时才返回 `CONTROLLER_SERVICE`。
  本任务没有 Controller 服务，所以返回空列表（`Capabilities` 为空切片，不是错误）。
  不声明 `VOLUME_ACCESSIBILITY_CONSTRAINTS`（架构 §5.4）。在 Driver 里用一个布尔字段 `controllerRegistered` 表示，T-10 置 true。
- `Probe`：依次执行 readiness 检查（见下），全部通过返回 `ready=true`；任一失败返回 `codes.FailedPrecondition`，
  信息里带失败原因（CSI spec：插件不健康返回 FAILED_PRECONDITION）。Probe 必须尊重 ctx：ctx 已取消时返回 `codes.Canceled`/`DeadlineExceeded`。

### `pkg/driver/probe.go`
```go
type check struct { name string; fn func(ctx context.Context) error }
```
- mode 为 node 或 all 时注册两项检查：`/dev/fuse` 存在且是字符设备；`exec.LookPath("mount.glusterfs")` 成功。
- controller 模式不注册检查。
- 检查函数的依赖（stat、lookPath）通过 Driver 的私有字段注入，测试中替换为假实现，**测试不得依赖本机是否有 /dev/fuse**。

### `pkg/driver/server.go`
- `grpc.NewServer(grpc.ChainUnaryInterceptor(recoverInterceptor, logInterceptor))`：
  - `recoverInterceptor`：捕获 panic → 返回 `codes.Internal`（信息 `"internal error"`，不带堆栈），并 `klog.ErrorS` 记录方法名与 panic 值。
  - `logInterceptor`：记录 method、耗时、gRPC 状态码。失败一律 `klog.ErrorS`；成功时 `/csi.v1.Identity/` 下的方法用 `V(5)`
    （livenessprobe 每几秒调一次 Probe，避免刷屏），其他方法用 `V(2)`。请求和响应内容只在 `V(5)` 下打印，
    且必须先经过 `protosanitizer.StripSecrets`。
- unix socket：
  - 监听前若路径已存在：用 `os.Lstat` 判断，**只有是 socket 才删除**；是普通文件/目录 → 返回错误，不删除。
  - 父目录不存在 → 返回错误（kubelet 负责创建目录，驱动不要 mkdir）。
  - 退出时删除自己创建的 socket 文件。
- ctx 取消时调用 `GracefulStop`，若 10s 内未结束则 `Stop`（等待用 goroutine + channel，必须有退出路径，不得泄漏）。
  `Serve` 因 Stop 返回的 `grpc.ErrServerStopped` 不算错误。

### `cmd/glusterfs-csi/main.go`
- `run(ctx context.Context, args []string, stdout, stderr io.Writer) error`：解析 / 校验参数 → `config.NewStore(opts.configPath)`
  （失败直接返回错误，进程退出码 1）→ 在 goroutine 中 `store.Run(ctx, 0)` → `driver.New` → `d.Run(ctx)`；
  返回前等待 `store.Run` 的 goroutine 结束。
- `main()` 用 `signal.NotifyContext(context.Background(), os.Interrupt, syscall.SIGTERM)`。
- `--config` 的帮助文本去掉 “(not used yet)”。
- 删除 “not implemented yet” 的输出及其测试。

## 测试（表驱动，断言行为）
1. `TestParseEndpoint`：`unix:///csi/csi.sock`、`unix://relative.sock`、`tcp://127.0.0.1:10000`、`tcp://[::1]:0`、`tcp://:10000` 合法；
   空串、`unix://`、`unix://   `、`tcp://`、`tcp://127.0.0.1`（无端口）、`tcp://h:99999`、`tcp://h:abc`、`http://x`、`UNIX:///a` 非法。
2. `TestParseMode`、`TestValidateDriverName`：合法 `glusterfs.csi.io`、`a`、`a-b.c1`、63 字符；非法见上文及空串。
3. `TestNew`：缺 NodeID 的 node/all 模式、非法 mode、非法驱动名、非法 endpoint 都返回错误；Version 为空时 GetPluginInfo 返回 `unknown`。
4. Identity（用 `bufconn` 起真实 gRPC server，通过 `csi.NewIdentityClient` 调用，覆盖拦截器）：
   - `GetPluginInfo` 返回配置的名字和版本；
   - `GetPluginCapabilities` 在本任务返回空列表；把 `controllerRegistered` 设为 true 时返回且只返回 `CONTROLLER_SERVICE`；
   - `Probe`：controller 模式 ready=true；node 模式假 stat/lookPath 全成功 ready=true；`/dev/fuse` 不存在、不是字符设备、
     `mount.glusterfs` 找不到 三种情况分别返回 `FailedPrecondition` 且信息含对应原因；ctx 已取消返回 Canceled。
5. `TestRecoverInterceptor`：直接调用拦截器，handler panic → 返回 `codes.Internal`，进程不崩。
6. `TestServeUnixSocket`：用 `os.MkdirTemp("", "gcsi")`（macOS 下 unix socket 路径不能超过 104 字节，不要用 `t.TempDir()`），
   - 预先放一个过期的 socket 文件 → Run 能启动并可调用 GetPluginInfo；
   - 预先放一个普通文件 → Run 返回错误且文件仍存在；
   - 父目录不存在 → 返回错误；
   - ctx 取消后 Run 在 2s 内返回 nil，socket 文件已删除。
7. main_test.go：`TestRun` 用临时合法 config 文件 + `tcp://127.0.0.1:0`，在 goroutine 中运行后 cancel，断言 2s 内返回 nil；
   config 文件不存在 / 非法时 `run` 立即返回错误。
