## 背景（必读）

T-15 交付了通道：`Executor` 在一台主机上执行一条 argv，`Failover` 在多台主机之间只在“远端什么都没执行”（`ErrConnect`）时换主机。
本任务在它之上封装 gluster 子命令，供 T-17（subdir 配额、扩容、GetCapacity）与 T-18（volume 模式建卷 / 删卷 / 扩容）使用。
本任务**不**决定这些结果映射成哪个 CSI 错误码，只给出可区分的 Go 错误。

架构师已在 Debian bullseye / bookworm / trixie 的软件包（GlusterFS **9.2 / 10.3 / 11.1**）上采集了每条命令的真实输出，
放在 `pkg/gluster/testdata/gluster-<版本>/`（采集脚本 `hack/capture-gluster-golden.sh`）。下面的规则全部来自这些样本，
实现前先读样本，不要凭记忆写 XML 结构。实测结论：

1. **退出码不可信，必须看 XML 的 `opRet`。** 几乎所有失败都是退出码 0、`opRet` 为 -1（`volume quota ... limit-usage` 对不存在的目录是 **-2**）。
   反过来，`volume quota <vol> list` 在 quota 未开启时退出码是 **2**，但 stdout 里仍有完整的 XML。
2. **`opErrno` 几乎总是通用的 30800**（只有 `volume info <不存在的卷>` 给 30806，`volume create` 重名给 0），不能用来分类；
   **只能按 `opErrstr` 文本分类**。三个版本的 `opErrstr` 文本完全相同（唯一差异是 `volume set` 未知选项的第二行“Did you mean …”）。
3. **glusterd 没运行时**：`gluster` 在 stdout（不是 stderr）打印 `Connection failed. Please check if gluster daemon is operational.`，
   退出码 1，没有 XML。此时远端什么都没执行。
4. 三个版本的 XML 结构相同，只有 9.2 的 `volume info` 多一个 `<stripeCount>`（解析时忽略未知元素即可）。
5. `limit-usage` 的大小写成非整数（如 `notasize`）时 gluster 退出码 1、只打印用法、没有 XML；本包只传十进制字节数，从源头避免。
   `2GB` 这种带单位的写法 gluster 也接受，但本包不用。
6. `volume quota <vol> list <不存在的路径>` 的 `opRet` 是 **0**，`<volQuota/>` 为空，原因只写在 stderr 里。
7. `volume quota <vol> list <存在但没设限额的目录>` 返回一条 `<limit>`，除 `used_space` 外各字段都是 `N/A`。

T-15 的 `SSHExecutor` 在非零退出时只返回 `*ExitError`（只带 stderr），**丢掉了 stdout**，结论 1 的退出码 2 和结论 3 的提示都在 stdout 里，
所以本任务先给 `ExitError` 加上 `Stdout`。

用户已决定（D-35）：
1. **“状态已经达成”算成功**：`VolumeStart` 对已启动的卷、`VolumeStop` 对已停止的卷、`QuotaEnable` 对已开启的 quota、
   `QuotaRemove` 对没有限额的目录都返回 `nil`。其它能识别的情况（卷不存在、卷已存在、quota 未开启、目录不存在……）返回带类型的哨兵错误，
   由 T-17 / T-18 映射成 CSI 错误码（例如 DeleteVolume 把 `ErrVolumeNotFound` 当成功）。
2. **glusterd 没运行就换下一台**：把结论 3 的情况转成包装 `ErrConnect` 的错误，`Failover` 因此会尝试下一台。远端什么都没执行，
   换主机不会让同一条命令执行两次（D-34 的前提仍然成立）。

### `ExitError.Stdout`（executor.go、ssh.go）
```go
type ExitError struct {
    Host    string
    Program string
    Code    int
    Stdout  []byte // 新增：命令写到 stdout 的内容，最多保留 64 KiB
    Stderr  []byte
}
```
- 新常量 `maxExitStdout = 64 << 10`；`SSHExecutor.Run` 在返回 `*ExitError` 时填入 `truncateOutput(stdout.Bytes(), maxExitStdout)`。
- `Error()` **不变**，不包含 stdout（stdout 可能很长，且是给解析用的）。
- 补测试：非零退出时 stdout 原样带回；超过 64 KiB 时截断到 64 KiB。

### `daemon.go`：glusterd 未运行 → `ErrConnect`
```go
// glusterdDownMessage is what the gluster CLI prints on stdout, with exit status 1,
// when it cannot reach the local glusterd. Verified on 9.2, 10.3 and 11.1.
const glusterdDownMessage = "Connection failed. Please check if gluster daemon is operational."

// daemonCheck wraps an Executor and turns "glusterd is not running" into an
// error that wraps ErrConnect, so that Failover tries the next server.
type daemonCheck struct{ Executor }

func (d daemonCheck) Run(ctx context.Context, host string, args ...string) ([]byte, error)
```
- 判定条件**全部**满足才转换：`errors.As(err, &exitErr)`、`exitErr.Program == "gluster"`、`exitErr.Code == 1`、
  `strings.TrimSpace(string(exitErr.Stdout)) == glusterdDownMessage`。不看 stderr。
- 转换后的错误：`fmt.Errorf("%w: glusterd is not running on %s", ErrConnect, host)`。**不得**再包住 `*ExitError`——
  `Failover.Run` 先用 `errors.As` 找 `ExitError`，找到就不换主机，包住它等于没转换。
- 其它错误、成功结果原样返回。

### `client.go`
```go
// Client runs gluster management commands on the servers of one cluster.
type Client struct { /* failover *Failover; hosts []string */ }

// NewClient returns a Client that runs commands through executor on hosts, in the
// failover order of Failover.
func NewClient(executor Executor, hosts []string) (*Client, error)
```
- `executor` 为 nil、`hosts` 为空、任一 host 不能通过 T-15 的 `validateHost` → 包装 `ErrInvalidCommand` 的错误。
- 内部：`&Failover{Executor: daemonCheck{executor}}`，`hosts` 复制一份保存。`Client` 可并发使用。

每个命令都经过同一个未导出的执行函数 `run(ctx, op string, args ...string) (*cliOutput, string /*host*/, error)`：
1. argv = `{"gluster", "--mode=script", "--xml", args...}`，交给 `Failover.Run`。
2. `Failover.Run` 返回错误时：如果 `errors.As(err, &exitErr)` 且 `exitErr.Stdout` 能解析成 `<cliOutput>`，**按 XML 继续**（结论 1 的退出码 2），
   并记住退出码；否则返回 `fmt.Errorf("gluster %s: %w", op, err)`——保留 `ErrConnect`、`*ExitError`、`*AllHostsFailedError`、
   ctx 错误，调用方仍能 `errors.Is` / `errors.As`。
3. 成功时解析 stdout。解析失败、根元素不是 `cliOutput`、缺 `opRet` → `ErrUnexpectedOutput`（见下）。
4. `opRet != 0`（-1、-2 以及任何非 0 值）→ `*CommandError`，按 `opErrstr` 分类。
5. `opRet == 0` 但退出码非 0 → `ErrUnexpectedOutput`（“exited with status N although opRet is 0”）。
6. 其余情况返回解析结果与执行的主机。

`op` 是不含参数值的子命令名，用于错误消息：`volume info`、`volume status`、`volume create`、`volume start`、`volume stop`、
`volume delete`、`volume set`、`volume quota enable`、`volume quota limit-usage`、`volume quota remove`、`volume quota list`。

错误：
```go
var (
    ErrVolumeNotFound   = errors.New("gluster volume does not exist")
    ErrVolumeExists     = errors.New("gluster volume already exists")
    ErrVolumeNotStarted = errors.New("gluster volume is not started")
    ErrVolumeStarted    = errors.New("gluster volume is started")        // delete 被拒：需先 stop
    ErrBrickInUse       = errors.New("brick is not available")           // 与已有 brick 重叠
    ErrUnknownOption    = errors.New("unknown gluster volume option")
    ErrQuotaNotEnabled  = errors.New("gluster quota is not enabled")
    ErrPathNotFound     = errors.New("directory does not exist in the gluster volume")
    ErrUnexpectedOutput = errors.New("unexpected gluster output")
)

// CommandError reports a gluster command that ran and answered with a non-zero opRet.
type CommandError struct {
    Op     string // 例如 "volume start"
    Volume string // 命令针对的卷名
    Host   string // 执行的主机
    Ret    int    // opRet
    Errno  int    // opErrno
    Errstr string // opErrstr 原文
    kind   error  // 分类得到的哨兵，未识别时为 nil
}
func (e *CommandError) Error() string
func (e *CommandError) Unwrap() error // 返回 kind
```
- `Error()` 形如 `gluster volume start t16vol on dxt-gluster-node-1: Volume t16vol already started (opRet -1, opErrno 30800)`；
  `Errstr` 部分用 T-15 的 `exitStderrMessage` 同样的规则（控制字符换空格、截断 256 字节、去掉无效 UTF-8），因为它可能是多行的。
- `ErrUnexpectedOutput` 的错误消息包含 op、主机和原因（XML 解码错误、缺什么字段、哪个值不是数字），**不包含整段输出**；
  引用的单个值同样按上面的规则截断。

**`opErrstr` 分类**（先 `strings.TrimSpace`；正则**两端锚定**，整个字符串必须匹配；只有 `ErrUnknownOption` 只看第一行）：

| 正则 | 结果 | 来源样本 |
|---|---|---|
| `^Volume does not exist$`、`^Volume \S+ does not exist$` | `ErrVolumeNotFound` | volume-info-missing、volume-{start,stop,delete,status}-missing、quota-enable-missing |
| `^Volume \S+ already exists$` | `ErrVolumeExists` | volume-create-exists |
| `^Brick: \S+ not available\. Brick may be containing or be contained by an existing brick\.$` | `ErrBrickInUse` | volume-create-bad-brick |
| `^Volume \S+ is not started$` | `ErrVolumeNotStarted` | volume-status-not-started、volume-status-stopped |
| `^Volume \S+ has been started\.\s*Volume needs to be stopped before deletion\.$` | `ErrVolumeStarted` | volume-delete-started |
| 第一行 `^option : \S+ does not exist$` | `ErrUnknownOption` | volume-set-bad-option |
| `^Quota is disabled, please enable quota$` | `ErrQuotaNotEnabled` | quota-limit-not-enabled、quota-list-not-enabled |
| `^Failed to get trusted\.gfid attribute on path \S+\. Reason : No such file or directory$` | `ErrPathNotFound` | quota-limit-missing-dir、quota-remove-missing-dir |
| `^Volume \S+ already started$` | 未导出 `errAlreadyStarted` | volume-start-again |
| `^Volume \S+ is not in the started state$` | 未导出 `errAlreadyStopped` | volume-stop-again |
| `^Quota is already enabled$` | 未导出 `errQuotaAlreadyEnabled` | quota-enable-again |
| `^No quota configured on volume \S+$` | 未导出 `errNoQuotaConfigured` | quota-list-no-limits |
| `^removexattr failed on \S+\. Reason : No data available$` | 未导出 `errNoQuotaLimit` | quota-remove-again |

未导出的几类只在对应方法里被吃掉（变成 `nil` 或空结果），在别的方法里出现时仍是一个 `*CommandError`（`errors.Is` 只能匹配到未导出哨兵）。
不匹配任何一行的 `opErrstr` → `kind` 为 nil 的 `*CommandError`。锚定是必须的：例如
`Staging failed on h2. Error: Volume foo does not exist` 是集群内部不一致，**不是**卷不存在。

### `validate.go`
在发出任何命令之前校验，失败返回包装 `ErrInvalidCommand` 的错误（不联网）：
- **卷名**：`volumeid.ValidateName("gluster volume", name)`（白名单、非 `.`/`..`、不以 `-` 开头）。
- **brick**：`type Brick struct { Host, Path string }`。`Host` 用 `validateHost`，另外不得以 `-` 开头、不得含 `:`
  （本包不支持 IPv6 字面量 brick）；`Path` 见下面的目录规则，且不能是 `/`。
- **目录路径**（brick 路径、quota 路径）：以 `/` 开头；`path.Clean(p) == p`；除 `/` 本身外，按 `/` 切分后的每一段都通过
  `volumeid.ValidateName`（因而拒绝 `..`、`.`、空段、`-` 开头）；总长不超过 4096 字节。
- **卷选项**：键 `^[a-z][a-z0-9-]*(\.[a-z0-9][a-z0-9-]*)+$`（如 `performance.cache-size`），值 `^[A-Za-z0-9._,:/*@+=%-]{1,1024}$` 且不以 `-` 开头。
- **配额字节数**：`1 ≤ bytes ≤ math.MaxInt64`，格式化为十进制（`strconv.FormatUint`），不带单位。

### `volume.go`
```go
const (
    VolumeCreated = "Created"
    VolumeStarted = "Started"
    VolumeStopped = "Stopped"
)

type Volume struct {
    Name            string
    ID              string
    Status          string            // statusStr：Created / Started / Stopped
    Type            string            // typeStr：Distribute / Replicate / Distributed-Replicate …
    BrickCount      int
    DistCount       int
    ReplicaCount    int
    ArbiterCount    int
    DisperseCount   int
    RedundancyCount int
    Bricks          []VolumeBrick     // 按 XML 顺序
    Options         map[string]string // options/option 的 name → value
}

type VolumeBrick struct {
    Host     string // brick <name> 中第一个 ":/" 之前的部分
    Path     string // 从 "/" 开始的部分
    HostUUID string
    Arbiter  bool   // isArbiter == 1
}

type BrickStatus struct {
    Host      string // <hostname>
    Path      string
    PeerID    string
    Online    bool   // <status> == 1
    Port      int    // "N/A" → 0
    PID       int    // "N/A" 或负数 → 0
    SizeTotal uint64 // 缺失或 "N/A" → 0
    SizeFree  uint64 // 同上
    Device    string
    FSName    string
}

type CreateOptions struct {
    Name    string
    Replica int     // 0：纯 distribute；否则 ≥ 2，且 len(Bricks) 是它的整数倍
    Bricks  []Brick // 至少 1 个，不得重复
    Force   bool    // 追加 "force"
}

func (c *Client) Volumes(ctx context.Context) ([]Volume, error)                  // volume info
func (c *Client) VolumeInfo(ctx context.Context, name string) (*Volume, error)  // volume info <name>
func (c *Client) VolumeStatus(ctx context.Context, name string) ([]BrickStatus, error) // volume status <name> detail
func (c *Client) VolumeCreate(ctx context.Context, opts CreateOptions) error
func (c *Client) VolumeStart(ctx context.Context, name string) error
func (c *Client) VolumeStop(ctx context.Context, name string) error
func (c *Client) VolumeDelete(ctx context.Context, name string) error
func (c *Client) VolumeSet(ctx context.Context, name, key, value string) error
```
- argv（`gluster --mode=script --xml` 之后）：`volume info`；`volume info <name>`；`volume status <name> detail`；
  `volume create <name> [replica <N>] <host:path>... [force]`；`volume start <name>`；`volume stop <name>`；`volume delete <name>`；
  `volume set <name> <key> <value>`。`--mode=script` 让 stop / delete 不再询问。
- `Volumes`：没有卷时返回空切片（volume-info-none、volume-info-after-delete）。`<count>` 与 `<volume>` 元素个数不一致 → `ErrUnexpectedOutput`。
- `VolumeInfo`：卷不存在 → `ErrVolumeNotFound`；结果不是恰好一个、名字不等于 `name` 的卷 → `ErrUnexpectedOutput`。
- 数字字段必须是整数，否则 `ErrUnexpectedOutput`；brick `<name>` 里没有 `":/"` → `ErrUnexpectedOutput`。
- `VolumeStatus`：只返回 brick 节点——跳过 `<path>` 不以 `/` 开头的节点（非 detail 输出里的 Self-heal Daemon、Quota Daemon 等，
  它们的 path 是 `localhost`）；`volName` 不等于 `name` → `ErrUnexpectedOutput`；卷未启动 → `ErrVolumeNotStarted`；
  不存在 → `ErrVolumeNotFound`。
- `VolumeStart`：`errAlreadyStarted` → `nil`。`VolumeStop`：`errAlreadyStopped` → `nil`（从未启动过的 Created 卷同样是这条消息，同样算成功）。
- `VolumeDelete`：不存在 → `ErrVolumeNotFound`；已启动 → `ErrVolumeStarted`。
- `VolumeCreate`：重名 → `ErrVolumeExists`；brick 重叠 → `ErrBrickInUse`。**不**做“同名同参数视为成功”的比较，那是 T-18 的事。
- 成功的变更操作（create / start / stop / delete / set）各记一行 `klog.V(2)`：op、卷名、主机。

### `quota.go`

- `QuotaEnable`：`errQuotaAlreadyEnabled` → `nil`；卷不存在 → `ErrVolumeNotFound`。
- `QuotaLimitUsage`：重复设置（同值或新值）都成功（quota-limit-again）；quota 未开启 → `ErrQuotaNotEnabled`；目录不存在 → `ErrPathNotFound`。
- `QuotaRemove`：`errNoQuotaLimit` → `nil`；目录不存在 → `ErrPathNotFound`。
- `QuotaList`：
  - `errNoQuotaConfigured` → 空切片、`nil`；quota 未开启（退出码 2 的 XML）→ `ErrQuotaNotEnabled`。
  - 每个 `<limit>` 的数值字段：十进制整数或（除 `path`、`used_space` 外）`N/A`；`soft_limit_percent` 是 `<整数>%` 或 `N/A`；
    `sl_exceeded` / `hl_exceeded` 是 `Yes`、`No` 或 `N/A`。其它值 → `ErrUnexpectedOutput`。
  - 指定了 `dirs` 时，结果里缺了其中某个目录（结论 6：不存在的目录 `opRet` 为 0、结果为空）→ 返回包装 `ErrPathNotFound` 的错误，
    消息里带上第一个缺失的目录。结果里出现没有请求的目录 → `ErrUnexpectedOutput`。
  - 不指定 `dirs` 时返回全部限额，按输出顺序。

## 验收

pi 必须运行并全部通过：
```
go build ./... && go vet ./... && golangci-lint run && go test -race ./...
golangci-lint run --build-tags integration ./pkg/gluster/...
go vet -tags integration ./pkg/gluster/...
go test -race -cover ./pkg/gluster/...      # 覆盖率 ≥ 90%，报告里给出数字
git status --short                          # 只出现允许改动的文件；testdata 没有改动
```

架构师验收：
1. 逐行评审，重点：是否有任何地方只看退出码；分类正则是否两端锚定；glusterd 未运行的转换是否仍包住 `ExitError`；
   每个进入 argv 的值是否都先校验；错误消息是否可能带出整段输出。
2. 变异测试（至少）：只看退出码不看 `opRet`；只把 `opRet == -1` 当失败（漏掉 -2）；`ExitError` 不带 Stdout；glusterd 未运行的错误包住
   `ExitError`；检测 glusterd 未运行时看 stderr 而不是 stdout；不检查退出码 1；`VolumeStart` / `VolumeStop` / `QuotaEnable` /
   `QuotaRemove` 不吃掉“已达成”的错误；去掉分类正则的锚定；`CommandError.Unwrap` 返回 nil；`QuotaList` 把 N/A 当错误或 `HasLimit`
   恒为 true；`QuotaList` 对缺失目录返回空结果；quota 路径允许 `..`；卷名不检查前导 `-`；配额字节数允许 0；`VolumeCreate` 漏掉
   `replica`；总是追加 `force`；退出码非 0 而 `opRet` 为 0 时当成功。
3. 真实集群：在 K8s 测试集群内跑 `TestIntegrationClientLifecycle`（3 台 Gluster 11.1，brick 根目录 `/data/brick1`），事后删除 brick 目录。
4. CI：现有 job 全绿（integration 测试不进 CI）。

## 不要做的事
- 不要解析人类可读的 gluster 输出，不要去掉 `--xml` 或 `--mode=script`；不要用 `opErrno` 分类。
- 不要修改 `pkg/gluster/testdata/` 里的任何文件，不要手写或“修正”样本；测试缺样本就在报告里说明。
- 不要加重试、sleep、轮询；同一命令不在同一主机上执行第二次，换主机只在 `ErrConnect` 时（由 `Failover` 负责）。
- 不要给 `limit-usage` 传带单位的大小；不要实现 arbiter、disperse、`volume get`、`volume quota ... default-soft-limit`、
  对象数配额、快照、brick 目录的创建与删除（T-18 / M4）。
- 不要接入 `pkg/driver`、`cmd/`、`pkg/config`，不要决定 CSI 错误码（T-17 / T-18）。
- 不要新增依赖，不要用第三方 XML 库。
