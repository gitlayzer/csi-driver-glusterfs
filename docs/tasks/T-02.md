## 背景
控制器无状态，删除/扩容/挂载所需的信息全部编码在 volume_id 里（`docs/architecture.md` §5.1）。
volume_id 的每个字段最终会进入 gluster 命令行参数和挂载路径，所以本包是注入防线的第一道。

格式（规范形式，大小写敏感）：
```
gfs:v1:<mode>:<clusterID>:<volume>[:<subdir>]
```

## 公开 API（签名必须一致）
```go
package volumeid

type Mode string

const (
	ModeStatic Mode = "static"
	ModeSubdir Mode = "subdir"
	ModeVolume Mode = "volume"
)

const (
	Prefix    = "gfs"
	Version   = "v1"
	MaxLength = 128 // CSI spec: string 字段默认上限 128 字节，volume_id 整体不得超过
)

// ErrInvalid 是本包所有校验/解析错误的哨兵；返回的错误必须满足 errors.Is(err, ErrInvalid)。
var ErrInvalid = errors.New("invalid volume id")

// ID 是解码后的 volume_id。
type ID struct {
	Mode      Mode
	ClusterID string
	Volume    string // Gluster 卷名
	Subdir    string // 可选，单级目录名；为空表示整个卷
}

// ValidateName 校验单个名字字段（clusterID、卷名、子目录名、以及以后 StorageClass 参数等），
// field 只用于错误信息。
func ValidateName(field, value string) error

// Validate 校验整个 ID（各字段 + 模式规则 + 编码后总长度）。
func (id ID) Validate() error

// Encode 先 Validate，再返回规范字符串。
func Encode(id ID) (string, error)

// Decode 解析并校验；成功时保证 Encode(Decode(s)) == s。
func Decode(s string) (ID, error)
```

## 规则

### ValidateName
1. 匹配 `^[A-Za-z0-9._-]{1,128}$`（预编译为包级变量，不要每次编译）。
2. 拒绝 `.` 和 `..`（路径穿越）。
3. 拒绝以 `-` 开头（防止作为 argv 时被 gluster/mount 当成选项，即参数注入）。
4. 错误信息格式：`invalid <field> "<value>": <原因>`，并 wrap `ErrInvalid`。
   值长度超过 128 时不要原样回显，改为写长度（`invalid volume: length 300 exceeds 128`）。

### Validate（模式规则）
| Mode | Subdir |
|---|---|
| `static` | 可选 |
| `subdir` | **必填** |
| `volume` | **必须为空** |
| 其他任何值（含空串、大小写不同如 `Static`） | 非法 |

- ClusterID、Volume 必填，均走 ValidateName；Subdir 非空时走 ValidateName。
- 编码后总长度 > `MaxLength` 字节 → 非法（错误信息写出实际长度）。

### Decode
- 按 `:` 切分（字段内不允许出现 `:`，所以切分是无歧义的）；段数只能是 5 或 6。
- 第 1 段必须是 `gfs`，第 2 段必须是 `v1`；未知版本的错误信息要写明 `unsupported version "v2"`。
- 6 段且最后一段为空（`...:vol:`）→ 非法。规范形式唯一，同一个卷只能有一种 id，这是幂等的前提。
- 空串、超过 `MaxLength` 的输入，先做长度检查再切分。
- 最后调用 `Validate`，模式规则与 Encode 一致。
- 不得 panic（任何输入）。

### 调用方约定（只写进包注释，不在本包实现）
本包只区分合法/非法。RPC 层再把 `ErrInvalid` 映射成状态码：
Node*/ValidateVolumeCapabilities/ControllerExpandVolume 返回 `NotFound`，DeleteVolume 返回成功
（csi-sanity 用 `some-vol-id` 这类非本驱动格式的 id 测这些路径）。

## 测试（`volumeid_test.go`，表驱动，断言行为）
1. `TestValidateName`：合法（`a`、`A-b_c.1`、128 个字符）；非法（空串、129 个字符、`.`、`..`、`-x`、`--help`、
   `a/b`、`a b`、`a:b`、`a;b`、`$(id)`、反引号、`a\nb`、`a\x00b`、`ä`、`*`）。非法用例要断言 `errors.Is(err, ErrInvalid)`。
   另有一条断言：300 字符的输入，错误信息中不含原值，只含长度。
2. `TestEncode`：三种模式的合法组合返回期望字符串；各种非法组合（未知模式、subdir 模式缺 Subdir、volume 模式带 Subdir、
   任一字段非法、总长度 129）返回 ErrInvalid。边界：总长度恰好 128 合法。
3. `TestDecode`：合法字符串得到期望 ID；非法：空串、`gfs:v1:static:c`（4 段）、7 段、前缀 `GFS`/`xfs`、版本 `v2`
   （断言信息含 `unsupported version`）、尾随冒号、字段注入字符、超长、`some-vol-id`、`reallyfakevolumeid`。
4. `TestRoundTrip`：对 TestEncode 的每个合法用例断言 `Decode(Encode(id)) == id`。
5. `FuzzDecode`：种子语料包含上面的合法/非法字符串；性质：不 panic；Decode 成功时 `Encode(id)` 成功且等于输入。
   `go test` 默认只跑种子即可，不要求在 CI 中跑模糊测试。

覆盖率要求：`go test -cover ./pkg/volumeid/` ≥ 90%。
