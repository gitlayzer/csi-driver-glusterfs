## 背景（必读）
M1 只有静态卷：管理员手写 PV，kubelet 调用 node 插件的 NodeStage/NodePublish。M1 **不部署 controller**（没有 CreateVolume），
所以本任务只有 node DaemonSet。相关决策（docs/decisions.md）：
- **D-2** 驱动名 `glusterfs.csi.io`；**D-3** 镜像 `ghcr.io/gitlayzer/glusterfs-csi`；**D-6** K8s 1.28–1.37，只用 1.28 已 GA 的 API。
- **D-19 / D-20**：容器内 FUSE + 恢复器。插件 Pod 重启会让本节点所有 Gluster 挂载失效，所以 DaemonSet 必须 `updateStrategy: OnDelete`，
  staging 记录在 `/var/lib/kubelet/plugins/glusterfs.csi.io/staged`（宿主机持久目录）。
- **D-21**：`hostNetwork: true` + `dnsPolicy: ClusterFirstWithHostNet`，容器用节点的 `/etc/hosts` 解析 Gluster 主机名；healthz 端口 29651。
- node 插件本身**不访问 K8s API**（配置来自挂载的 ConfigMap 文件），因此 ServiceAccount 不绑定任何 Role，且不挂载 token。

二进制的 flag（`cmd/glusterfs-csi/main.go`）：`--mode`、`--endpoint`、`--nodeid`、`--drivername`、`--config`、`--mount-log-dir`、
`--state-dir`、`--recovery-interval`，以及 klog 的 `--v`。配置文件格式（`pkg/config`）：
```json
[{"clusterID": "prod", "servers": ["gluster-1.example.com", "gluster-2.example.com", "gluster-3.example.com"]}]
```

## 设计

所有资源都带标签 `app.kubernetes.io/name: glusterfs-csi` 与 `app.kubernetes.io/part-of: glusterfs-csi`（示例资源除外，见下）。
YAML 用 2 空格缩进，每个文件只放一个资源，文件头一行注释说明用途。不要用 `commonLabels`（已废弃）。

### `deploy/kustomize/base`
`kustomization.yaml`：`namespace: glusterfs-csi`；`resources` 依次为 namespace、csidriver、serviceaccount、node-daemonset；
`images` 把 `ghcr.io/gitlayzer/glusterfs-csi` 的 `newTag` 设为 `main`。文件内注释写明：base **故意不含** ConfigMap
`glusterfs-csi-config`，必须通过 overlay 提供（参考 `overlays/sample`），否则 Pod 会卡在 ContainerCreating。

`namespace.yaml`：Namespace `glusterfs-csi`，标签 `pod-security.kubernetes.io/enforce|audit|warn: privileged`（node 插件需要特权）。

`csidriver.yaml`：`storage.k8s.io/v1` CSIDriver `glusterfs.csi.io`：
`attachRequired: false`、`podInfoOnMount: false`、`fsGroupPolicy: File`、`volumeLifecycleModes: [Persistent]`、`requiresRepublish: false`、
`storageCapacity: false`。不写其它字段。

`serviceaccount.yaml`：ServiceAccount `glusterfs-csi-node`，`automountServiceAccountToken: false`。

`node-daemonset.yaml`：`apps/v1` DaemonSet `glusterfs-csi-node`
- 标签与 selector：`app.kubernetes.io/name: glusterfs-csi`、`app.kubernetes.io/component: node`（selector 只用这两个），
  Pod 模板同样带 `app.kubernetes.io/part-of`。
- `updateStrategy: {type: OnDelete}`，并加注释说明原因（重启插件会断开本节点所有挂载，必须由管理员逐节点删除 Pod 升级）。
- Pod：`serviceAccountName: glusterfs-csi-node`、`automountServiceAccountToken: false`、`hostNetwork: true`、
  `dnsPolicy: ClusterFirstWithHostNet`、`priorityClassName: system-node-critical`、`nodeSelector: {kubernetes.io/os: linux}`、
  `tolerations: [{operator: Exists}]`。
- 容器 1 `glusterfs-csi`：
  - `image: ghcr.io/gitlayzer/glusterfs-csi:main`，`imagePullPolicy: IfNotPresent`
  - `args`（逐项写全，即使与默认值相同，便于对照挂载路径）：`--mode=node`、`--endpoint=unix:///csi/csi.sock`、`--nodeid=$(NODE_ID)`、
    `--config=/etc/glusterfs-csi/config.json`、`--state-dir=/var/lib/kubelet/plugins/glusterfs.csi.io/staged`、
    `--recovery-interval=60s`、`--mount-log-dir=/var/log/glusterfs/csi`、`--v=2`
  - `env`：`NODE_ID` 取 `fieldRef: spec.nodeName`
  - `securityContext: {privileged: true}`（`/dev/fuse` 与 Bidirectional 挂载传播都需要）
  - `ports: [{name: healthz, containerPort: 29651, protocol: TCP}]`
  - `livenessProbe`：`httpGet {path: /healthz, port: healthz}`，`initialDelaySeconds: 10`、`periodSeconds: 20`、`timeoutSeconds: 10`、
    `failureThreshold: 5`。注释说明：探针失败会重启容器并断开挂载，所以阈值放宽。
  - `resources`：只有 `requests {cpu: 20m, memory: 64Mi}`，**不设 limits**；注释说明：FUSE 进程在此容器内，被 OOM 杀掉会断开本节点所有挂载。
  - `volumeMounts`：`socket-dir` → `/csi`；`kubelet-dir` → `/var/lib/kubelet`，`mountPropagation: Bidirectional`；
    `config` → `/etc/glusterfs-csi`，`readOnly: true`；`mount-log` → `/var/log/glusterfs/csi`。
- 容器 2 `node-driver-registrar`：
  - `image: registry.k8s.io/sig-storage/csi-node-driver-registrar:v2.18.0`
  - `args`：`--v=2`、`--csi-address=/csi/csi.sock`、`--kubelet-registration-path=/var/lib/kubelet/plugins/glusterfs.csi.io/csi.sock`
  - `livenessProbe.exec.command`：`[/csi-node-driver-registrar, --kubelet-registration-path=/var/lib/kubelet/plugins/glusterfs.csi.io/csi.sock, --mode=kubelet-registration-probe]`，
    `initialDelaySeconds: 30`、`periodSeconds: 90`、`timeoutSeconds: 15`
  - `resources`：`requests {cpu: 10m, memory: 20Mi}`、`limits {memory: 64Mi}`
  - `volumeMounts`：`socket-dir` → `/csi`；`registration-dir` → `/registration`
- 容器 3 `liveness-probe`：
  - `image: registry.k8s.io/sig-storage/livenessprobe:v2.20.0`
  - `args`：`--v=2`、`--csi-address=/csi/csi.sock`、`--http-endpoint=:29651`、`--probe-timeout=5s`
  - `resources`：`requests {cpu: 10m, memory: 20Mi}`、`limits {memory: 64Mi}`
  - `volumeMounts`：`socket-dir` → `/csi`
- `volumes`：
  - `socket-dir`：hostPath `/var/lib/kubelet/plugins/glusterfs.csi.io`，`type: DirectoryOrCreate`
  - `registration-dir`：hostPath `/var/lib/kubelet/plugins_registry`，`type: Directory`
  - `kubelet-dir`：hostPath `/var/lib/kubelet`，`type: Directory`
  - `config`：configMap `glusterfs-csi-config`（不加 `optional`、不加 `items`、**不能用 subPath 挂载**，否则热更新失效）
  - `mount-log`：hostPath `/var/log/glusterfs/csi`，`type: DirectoryOrCreate`
- 文件头注释说明：所有 hostPath 假定 kubelet 根目录是 `/var/lib/kubelet`（k3s/microk8s 等需改路径）。

### `deploy/kustomize/overlays/sample`
`kustomization.yaml`：`namespace: glusterfs-csi`；`resources: [../../base]`；
`configMapGenerator`：`name: glusterfs-csi-config`、`files: [config.json]`、`options: {disableNameSuffixHash: true}`，
注释说明：不加哈希后缀是因为 DaemonSet 为 OnDelete，换名不会滚动 Pod；插件会热加载同名 ConfigMap 的变更（约 10s + kubelet 同步周期）。
`images`：`ghcr.io/gitlayzer/glusterfs-csi` 的 `newTag: main`，注释建议固定为 `sha-<短 sha>` 或发布版本。
`config.json`：上面背景中的示例（主机名形式的 servers，没有 `executorSecretRef`），格式化为多行、2 空格缩进。

### `deploy/kustomize/examples/static`
示例资源的标签用 `app.kubernetes.io/name: rwx-writer`（PV/PVC 可不加标签）。
- `kustomization.yaml`：`namespace: glusterfs-csi-example`；resources 为 namespace、pv、pvc、deployment。
- `namespace.yaml`：Namespace `glusterfs-csi-example`。
- `pv.yaml`：PV `glusterfs-static-example`：`capacity.storage: 10Gi`、`accessModes: [ReadWriteMany]`、`persistentVolumeReclaimPolicy: Retain`、
  `storageClassName: ""`、`volumeMode: Filesystem`、`claimRef {namespace: glusterfs-csi-example, name: shared-data}`、
  `csi {driver: glusterfs.csi.io, volumeHandle: "gfs:v1:static:prod:shared-vol", volumeAttributes {clusterID: prod, volume: shared-vol}}`。
  注释说明 volumeHandle 格式 `gfs:v1:static:<clusterID>:<glusterVolume>[:<subdir>]`，clusterID 必须出现在 ConfigMap 中。
- `pvc.yaml`：PVC `shared-data`：`accessModes: [ReadWriteMany]`、`storageClassName: ""`、`volumeName: glusterfs-static-example`、
  `resources.requests.storage: 10Gi`。
- `deployment.yaml`：Deployment `rwx-writer`，`replicas: 3`，
  `topologySpreadConstraints: [{maxSkew: 1, topologyKey: kubernetes.io/hostname, whenUnsatisfiable: DoNotSchedule, labelSelector: {matchLabels: {app.kubernetes.io/name: rwx-writer}}}]`。
  容器 `writer`：`image: docker.io/library/busybox:1.37.0`；env `NODE_NAME`（spec.nodeName）、`POD_NAME`（metadata.name）；
  `command: [sh, -c, <脚本>]`，脚本每 5 秒向 `/data/$POD_NAME.log` 追加一行 `<UTC 时间> <NODE_NAME> <POD_NAME> <递增序号>`；
  `volumeMounts: [{name: data, mountPath: /data, mountPropagation: HostToContainer}]`，注释引用 D-19（插件重启后自动看到恢复的挂载）；
  `livenessProbe.exec.command: [ls, /data]`，`periodSeconds: 10`、`timeoutSeconds: 5`、`failureThreshold: 3`
  （注释：挂载失效时重启容器，作为未声明 HostToContainer 时的兜底）；
  `resources.requests {cpu: 10m, memory: 16Mi}`、`limits {memory: 32Mi}`。卷 `data` 引用 PVC `shared-data`。
  示例以 root 运行（Gluster 卷根目录默认 root:root 755），注释说明。

### `hack/verify-manifests.sh`
bash，`set -euo pipefail`，先 `cd` 到仓库根目录（相对脚本位置）。环境变量：`KUBECTL`（默认 `kubectl`）、`KUBECONFORM`（默认 `kubeconform`，
允许是带参数的命令如 `docker run --rm -i ghcr.io/yannh/kubeconform:v0.8.0`，用 `read -r -a` 拆成数组后执行，不要用 eval）、
`K8S_VERSION`（默认 `1.28.0`）。对 `base`、`overlays/sample`、`examples/static` 依次执行
`"$KUBECTL" kustomize deploy/kustomize/<dir> | <kubeconform 数组> -strict -summary -kubernetes-version "$K8S_VERSION" -`，
每个目录前打印 `==> <dir>`；任一失败即退出非零。另外检查渲染结果中的每个 `image:` 都带显式 tag 且不是 `latest`，否则报错退出。
脚本需通过 `shellcheck`（若本机有）。
