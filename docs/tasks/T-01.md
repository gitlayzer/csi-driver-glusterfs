# T-01 仓库脚手架

**状态**：已验收（2026-10-31）
**执行者**：pi / deepseek-flash
**允许改动的文件**：下文“交付物”列出的文件；不得修改 `docs/`、`AGENTS.md`。

## 输入参数
- Go module：`github.com/gitlayzer/csi-driver-glusterfs`
- 默认驱动名：`glusterfs.csi.io`（可通过 `--drivername` 覆盖）
- Go 版本：go.mod 写 `go 1.24`（兼容下游构建），本地工具链更高无妨

## 交付物
1. `go.mod`：依赖仅限
   - `github.com/container-storage-interface/spec`（最新 v1.x 稳定版）
   - `google.golang.org/grpc`
   - `k8s.io/klog/v2`
   - `github.com/kubernetes-csi/csi-lib-utils`（protosanitizer）
2. `cmd/glusterfs-csi/main.go`：flag 解析
   - `--endpoint`（默认 `unix:///csi/csi.sock`）
   - `--nodeid`（mode 为 node/all 时必填）
   - `--mode`（`controller|node|all`，默认 `all`）
   - `--drivername`（默认 `glusterfs.csi.io`）
   - `--config`（默认 `/etc/glusterfs-csi/config.json`，本任务只解析不使用）
   - `--version` 打印版本后退出
   - 参数校验失败以非零码退出并打印原因；本任务里 main 校验参数后打印 “not implemented yet” 并退出 0 即可，gRPC server 在 T-04 实现。
3. `pkg/version/version.go`：`Version`、`GitCommit`、`BuildDate` 通过 `-ldflags -X` 注入，提供 `Get()` 返回结构体。
4. `Makefile`：`build`（输出 `bin/glusterfs-csi`，注入版本）、`test`（`go test -race ./...`）、`lint`（`golangci-lint run`）、`image`（`docker buildx build --platform linux/amd64,linux/arm64`，`IMAGE`（默认 `ghcr.io/gitlayzer/glusterfs-csi`）/ `TAG` 变量）、`clean`。
5. `.golangci.yml`：启用 govet、errcheck、staticcheck、ineffassign、unused、gosec、revive、misspell、gofmt、goimports（与当前安装的 golangci-lint 版本配置格式匹配，先运行 `golangci-lint --version` 确认）。
6. `Dockerfile`：多阶段
   - builder：受支持的 Go 版本（验收时改为 `golang:1.27`，基础镜像可用 `GO_IMAGE`/`BASE_IMAGE` 覆盖），`CGO_ENABLED=0`，支持 `TARGETOS/TARGETARCH`
   - runtime：`debian:trixie-slim`（验收时由 bookworm 改为 trixie，客户端 11.1 与服务端一致） + `glusterfs-client`（提供 `mount.glusterfs`）+ `ca-certificates`，清理 apt 缓存
   - `ENTRYPOINT ["/glusterfs-csi"]`
7. `.dockerignore`、`.gitignore`（bin/、覆盖率文件等）
8. `LICENSE`：Apache-2.0 全文
9. 单元测试：`cmd/glusterfs-csi` 中把参数校验抽成 `validateFlags(opts) error`，表驱动测试覆盖：非法 mode、node 模式缺 nodeid、controller 模式无需 nodeid、空 endpoint、非 `unix://` 和 `tcp://` 的 endpoint。

## 验收标准

- 无多余依赖、无 `docs/` 改动。
