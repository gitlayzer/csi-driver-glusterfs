## 背景（必读）
到 T-12 为止，驱动只能用 kustomize 安装（`deploy/kustomize/base` + `overlays/sample`）。本任务提供一个 Helm chart，
渲染结果必须与 kustomize **逐字等价**，并由脚本和 CI 持续保证。相关决策（docs/decisions.md）：
- **D-32**：chart 形态 —— 手写、资源名固定与 kustomize 相同、不含 Namespace、`clusters` 原样透传进 ConfigMap、不加 checksum 注解、
  Helm 专属标签只加在顶层 `metadata.labels`。
- **D-33**：一致性校验 —— `hack/verify-helm.sh` 与 CI `helm` job（Helm v3 与 v4 各一次）。
- **D-6**：K8s 1.28 – 1.37。**D-21 / D-28**：hostNetwork 的原因。**D-29**：示例 StorageClass。

动手前先完整读一遍 `deploy/kustomize/base/` 的每个文件和 `overlays/sample/`：chart 的模板就是这些文件参数化之后的样子，
**注释（解释“为什么”的那些）原样搬进模板**，资源顺序、字段顺序、容器顺序、args 顺序都保持一致。
`hack/verify-manifests.sh` 是校验脚本的写法范本（`set -euo pipefail`、环境变量、`read -r -a` 拆分命令、不用 eval）。

### `Chart.yaml`
```yaml
apiVersion: v2
name: glusterfs-csi
description: Kubernetes CSI driver for GlusterFS
type: application
version: 0.1.0
appVersion: "main"
kubeVersion: ">=1.28.0-0"
home: https://github.com/gitlayzer/csi-driver-glusterfs
sources:
  - https://github.com/gitlayzer/csi-driver-glusterfs
```
可以加 `keywords`；不要加 `dependencies`、`icon`、`maintainers`。

### `values.yaml`
键名与默认值**必须**如下（每个键上方写英文注释说明用途；默认值逐字对应 kustomize base 的值）：
```yaml
clusters: []
# 注释里给出示例：
#  - clusterID: prod
#    servers: [gluster-1.example.com, gluster-2.example.com, gluster-3.example.com]

image:
  repository: ghcr.io/gitlayzer/glusterfs-csi
  tag: ""            # empty: .Chart.AppVersion
  pullPolicy: IfNotPresent

imagePullSecrets: []

sidecars:
  nodeDriverRegistrar:
    image:
      repository: registry.k8s.io/sig-storage/csi-node-driver-registrar
      tag: v2.18.0
    resources: {requests: {cpu: 10m, memory: 20Mi}, limits: {memory: 64Mi}}
  livenessProbe:
    image:
      repository: registry.k8s.io/sig-storage/livenessprobe
      tag: v2.20.0
    resources: {requests: {cpu: 10m, memory: 20Mi}, limits: {memory: 64Mi}}
  provisioner:
    image:
      repository: registry.k8s.io/sig-storage/csi-provisioner
      tag: v6.4.0
    timeout: 60s
    resources: {requests: {cpu: 10m, memory: 32Mi}, limits: {memory: 256Mi}}

logLevel: 2
kubeletDir: /var/lib/kubelet

node:
  recoveryInterval: 10s
  priorityClassName: system-node-critical
  nodeSelector: {kubernetes.io/os: linux}
  tolerations: [{operator: Exists}]
  affinity: {}
  resources: {requests: {cpu: 20m, memory: 64Mi}}

controller:
  replicas: 2
  priorityClassName: system-cluster-critical
  nodeSelector: {kubernetes.io/os: linux}
  tolerations: []
  affinity: <与 controller-deployment.yaml 中的 podAntiAffinity 逐字相同>
  resources: {requests: {cpu: 20m, memory: 64Mi}}

storageClasses: []
```
上面的流式写法只是为了规格简短，values.yaml 里用普通的块式 YAML。
- `logLevel` 用于全部容器的 `--v=`（驱动与三个 sidecar）。
- sidecar 镜像不渲染 `imagePullPolicy`（kustomize 里也没有）。
- `imagePullSecrets`、`affinity`、`tolerations`、`nodeSelector` 为空时**不渲染该键**（用 `with`），所以默认值下 node 没有 `affinity`、
  controller 没有 `tolerations`，与 kustomize 一致。`imagePullSecrets` 非空时同时加到两个 Pod。
- 端口 29651/29652/29653、socket 路径、`/etc/glusterfs-csi`、`/var/log/glusterfs/csi`、`/var/lib/glusterfs-csi/controller`
  **不做成参数**，写死在模板里。

### `templates/_helpers.tpl`
只定义这些 helper（名字统一用 `glusterfs-csi.` 前缀）：
- `glusterfs-csi.labels`：顶层 `metadata.labels` 用：`app.kubernetes.io/name: glusterfs-csi`、`app.kubernetes.io/part-of: glusterfs-csi`、
  `helm.sh/chart: <name>-<version>`（`+` 换成 `_`）、`app.kubernetes.io/managed-by: {{ .Release.Service }}`、
  `app.kubernetes.io/instance: {{ .Release.Name }}`、`app.kubernetes.io/version: {{ .Chart.AppVersion | quote }}`。
  有 component 的资源在其后追加 `app.kubernetes.io/component: node|controller`。
- `glusterfs-csi.image`：`repository:tag`，tag 为空时取 `.Chart.AppVersion`。
- 可选：`glusterfs-csi.pluginDir`（`<kubeletDir>/plugins/glusterfs.csi.io`）等纯拼接 helper。

**Pod 模板的标签**只有 `app.kubernetes.io/name`、`app.kubernetes.io/part-of`、`app.kubernetes.io/component` 三个，**selector** 只有
`name` 与 `component` 两个 —— 与 kustomize 逐字相同，不得加入 Helm 标签（selector 不可变，D-32）。

### 资源
- 资源名全部写死，与 kustomize 相同：CSIDriver `glusterfs.csi.io`，ServiceAccount `glusterfs-csi-node`、`glusterfs-csi-controller`，
  DaemonSet `glusterfs-csi-node`，Deployment `glusterfs-csi-controller`，ClusterRole/ClusterRoleBinding `glusterfs-csi-provisioner`，
  Role/RoleBinding `glusterfs-csi-provisioner-cfg`，ConfigMap `glusterfs-csi-config`。名称与 kustomize 有任何出入以 kustomize 为准。
- 所有命名空间级资源写 `namespace: {{ .Release.Namespace }}`；ClusterRoleBinding / RoleBinding 的 subject namespace 也是它。
  **不要**创建 Namespace 对象。
- `kubeletDir` 替换 node DaemonSet 中**每一处** `/var/lib/kubelet`：`--state-dir`、registrar 的 `--kubelet-registration-path`
  （args 与 livenessProbe 里各一处）、`socket-dir` / `registration-dir` / `kubelet-dir` 三个 hostPath，以及 `kubelet-dir` 的
  `mountPath`（Bidirectional 挂载的容器内路径必须与宿主机路径相同，kubelet 传来的 target path 是宿主机路径）。
  把 node-daemonset.yaml 文件头里“其它发行版需要打补丁”的注释改为说明 `kubeletDir`。
- `node.recoveryInterval` → `--recovery-interval=`；`sidecars.provisioner.timeout` → `--timeout=`（保留原有注释）。
- ConfigMap：
  ```yaml
  data:
    config.json: |
      {{- .Values.clusters | toPrettyJson | nindent 4 }}
  ```
  （写法可调整，结果必须是合法 JSON 数组。）渲染前校验：`clusters` 为空时 `fail`，消息里包含 `clusters`；每一项用 `required`
  检查 `clusterID` 与 `servers`（消息形如 `clusters[0].clusterID is required`）。除此之外不做字段检查、不改名、不过滤 ——
  原样透传（D-32），驱动加载配置时自己校验。
- 不加 `checksum/config` 之类的注解（D-32）。
- `storageclass.yaml`：对 `storageClasses` 每一项渲染一个 StorageClass：
  `name`（required）、可选 `annotations`（用于默认 StorageClass 注解）、`labels`（加在 `glusterfs-csi.labels` 之后）、
  `provisioner: glusterfs.csi.io`（写死）、`parameters`（required，原样输出）、`reclaimPolicy`（默认 `Delete`）、
  `volumeBindingMode`（默认 `Immediate`）、`allowVolumeExpansion`（默认 `false`，注意 `false` 不能被 `default` 吞掉，
  用 `hasKey` 判断）、`mountOptions`（非空才渲染）。三个默认字段**总是**显式渲染。
- `NOTES.txt`（英文，简短）：查看 Pod 与 CSINode 的命令；命名空间若启用了 Pod Security Admission，需要
  `pod-security.kubernetes.io/enforce=privileged` 标签；node DaemonSet 是 `OnDelete`，`helm upgrade` 后要逐节点腾空并删除插件 Pod；
  修改 `clusters` 后驱动约 10s 内热加载，无需重启；资源名固定，一个集群只能安装一份。

### `ci/sample-values.yaml`
只包含：
- `clusters`：与 `deploy/kustomize/overlays/sample/config.json` 相同（clusterID `prod`，三个 `gluster-N.example.com`）；
- `storageClasses`：一项 `glusterfs-subdir`，`parameters`、`reclaimPolicy`、`volumeBindingMode`、`allowVolumeExpansion`
  与 `deploy/kustomize/examples/dynamic/storageclass.yaml` 相同。

其余全部用默认值 —— 这正是“默认值与 kustomize 等价”的证明。

### `hack/verify-helm.sh`
头部注释写清用途与环境变量。环境变量（均有默认值）：`HELM`（`helm`）、`KUBECTL`（`kubectl`）、`KUBECONFORM`（`kubeconform`）、
`YQ`（`docker run --rm -i mikefarah/yq:4.54.1`）、`K8S_VERSION`（`1.28.0`）。`KUBECONFORM` 与 `YQ` 用 `read -r -a` 拆成数组，
不用 eval。临时文件放 `mktemp -d`，`trap` 清理。每一步打印 `==> 步骤名`，任何一步失败脚本以非零退出。步骤：

1. `helm version --short` 打印版本。
2. `helm lint --strict <chart> -f <chart>/ci/sample-values.yaml`。
3. **默认值必须失败**：`helm template` 不带 values 文件，必须非零退出且 stderr 含 `clusters`；`--set 'clusters[0].servers={a}'`
   也必须失败且含 `clusterID`。期望之外的成功要打印清楚的错误并退出 1。
4. 渲染：`helm template glusterfs-csi <chart> --namespace glusterfs-csi --kube-version "${K8S_VERSION}" -f ci/sample-values.yaml`。
5. kubeconform：`-strict -summary -kubernetes-version "${K8S_VERSION}"` 校验第 4 步的结果。
6. 等价比较：
   - kustomize 侧：`kubectl kustomize deploy/kustomize/overlays/sample`；
   - Helm 侧：第 4 步的结果去掉 `StorageClass`；
   - 两侧都用下面的 yq 表达式归一化（架构师已用 yq 4.54.1 验证可用；Namespace 在这里去掉，Helm 侧本来就没有），然后 `diff -u`，
     有差异则打印 diff 并失败：
     ```
     [.] | map(select(. != null and .kind != "Namespace"))
     | map(del(.metadata.labels."helm.sh/chart", .metadata.labels."app.kubernetes.io/managed-by", .metadata.labels."app.kubernetes.io/instance", .metadata.labels."app.kubernetes.io/version"))
     | map(with(select(.kind == "ConfigMap" and .data."config.json"); .data."config.json" |= (from_json | sort_keys(..) | to_json(0))))
     | sort_by(.kind, .metadata.name) | .[]
     | (... comments="") | sort_keys(..) | (... style="") | split_doc
     ```
     调用方式：`"${yq[@]}" ea "${expr}" - <file`（表达式作为参数传入，不挂载卷，这样 `YQ` 换成任何 docker 镜像或本地二进制都能用）。
     注意 Helm 专属标签只从**顶层** `.metadata.labels` 删除；如果 Pod 模板里出现了 Helm 标签，diff 就应该失败。
7. StorageClass 比较：分别从第 4 步结果与 `kubectl kustomize deploy/kustomize/examples/dynamic` 中取出 StorageClass
   `glusterfs-subdir`，比较 `{provisioner, parameters, reclaimPolicy, volumeBindingMode, allowVolumeExpansion}`（同样 yq 取值、
   `sort_keys`），不同则失败。
8. `kubeletDir`：`--set kubeletDir=/data/kubelet` 渲染（加 sample values），结果中 `/var/lib/kubelet` 必须出现 0 次、
   `/data/kubelet` 至少出现一次，并通过 kubeconform。
9. 最后打印 `Helm chart verified with <helm 版本> against Kubernetes ${K8S_VERSION}.`

必须通过 shellcheck。

在报告里贴出三次失败的关键输出。

架构师验收：

3. 真实集群：卸下 kustomize 安装的对象后用 `helm install` 安装（镜像固定为当前 `sha-` tag），node 与 controller 全部 Ready，
   CSINode 注册，动态卷示例 PVC Bound 并可跨节点读写；`helm upgrade` 修改 `clusters` 后驱动热加载；`helm uninstall` 只留下
   命名空间。之后按用户决定保留 Helm 安装或换回 kustomize。

## 不要做的事
- 不要改 kustomize 清单来“迁就” chart；不一致时改 chart。kustomize 里确实有错，在报告里写出来，由架构师处理。
- 不要用 `.Release.Name` 拼资源名，不要加 `fullnameOverride` / `nameOverride`。
- 不要加 Namespace、PodDisruptionBudget、ServiceMonitor、NetworkPolicy、Helm hook、`lookup`、`values.schema.json`。
- 不要加 checksum 注解；不要让 Helm 标签进入 Pod 模板或 selector。
- 不要在脚本、chart、CI 中写镜像加速器、代理地址或任何凭据。
- 不要把端口、容器内路径做成参数。
