## 设计

### `pkg/driver/parameters.go`
```go
// Parameter keys of a StorageClass (D-22). They are case sensitive.
const (
	paramClusterID        = "clusterID"
	paramProvisioningMode = "provisioningMode"
	paramParentVolume     = "parentVolume"
	paramOnDelete         = "onDelete"
	paramQuota            = "quota"

	// reservedParamPrefix is the prefix of the parameters the CSI sidecars add
	// or interpret themselves (secrets, --extra-create-metadata). They are not
	// parameters of this driver and are ignored.
	reservedParamPrefix = "csi.storage.k8s.io/"
)

// deletePolicy is what DeleteVolume does with the directory of a volume.
type deletePolicy string

const (
	deletePolicyDelete  deletePolicy = "delete"
	deletePolicyRetain  deletePolicy = "retain"
	deletePolicyArchive deletePolicy = "archive"
)

// volumeParameters are the validated StorageClass parameters of a volume.
type volumeParameters struct {
	ClusterID    string
	Mode         volumeid.Mode // always volumeid.ModeSubdir in M2
	ParentVolume string
	OnDelete     deletePolicy
}

// errInvalidParameters is wrapped by every error of parseVolumeParameters.
var errInvalidParameters = errors.New("invalid storage class parameters")

func parseVolumeParameters(params map[string]string) (volumeParameters, error)
```
规则（全部问题一次报告：按 key 排序逐个检查，用 `errors.Join` 合并，外层 `fmt.Errorf("%w: %w", errInvalidParameters, joined)`；
同样的输入永远得到同样的消息）：
- `clusterID`：必填；`volumeid.ValidateName`。是否存在于配置由调用方判断（解析是纯函数）。
- `provisioningMode`：可选，缺省 `subdir`。`subdir` → `volumeid.ModeSubdir`；`static` → 错误（"static volumes are not provisioned,
  create the PersistentVolume by hand"）；`volume` → 错误（"provisioningMode \"volume\" is not supported yet"）；其它值 → 错误并列出允许值。
- `parentVolume`：`subdir` 模式必填；`volumeid.ValidateName`。
- `onDelete`：可选，缺省 `delete`；只接受 `delete`、`retain`、`archive`。
- `quota`：可选；只接受 `"true"`、`"false"`；`"false"` 无效果；`"true"` → 错误（"quota is not supported yet"，配额在 M3 实现，
  静默忽略会让用户以为容量受限）。
- 以 `csi.storage.k8s.io/` 开头的 key：忽略。
- 其它任何 key（包括大小写不同的已知 key，如 `clusterid`）→ 错误（"unknown parameter %q"）。
- 值原样使用，不 trim；空字符串按"提供了但非法"处理（如 `clusterID: ""` 是错误，不是缺省）。
- 错误消息中回显的值用 `%q`，长度超过 `volumeid.MaxLength` 的值只报长度（参照 `echoVolumeID`），避免把超长输入写进日志。

### `pkg/driver/capability.go`
新增 Controller 侧检查，复用已有的访问模式表：
```go
// checkControllerCapability validates c for the controller service. A
// malformed capability is an InvalidArgument status error. A well formed one
// the driver does not support returns supported=false and the reason, which
// ValidateVolumeCapabilities reports in its message and CreateVolume (T-11)
// turns into InvalidArgument.
func checkControllerCapability(c *csi.VolumeCapability) (supported bool, reason string, err error)
```
- 畸形（与 Node 侧相同的判定）：nil、无 access mode、`UNKNOWN`、协议未定义的模式值、无 access type → `InvalidArgument`。
- 不支持：Block → `"block access type is not supported"`；`fs_type` 非空且不是 `mounter.FSType` → 说明原因。
- 其余（任何已定义的访问模式 + Mount 类型）→ supported。
- 把 Node 侧与 Controller 侧共同的畸形判定提成一个内部函数，**不要复制**；`validateNodeCapability` 的行为与错误码必须不变（现有测试继续通过）。

### `pkg/driver/controller.go`
```go
// controllerService implements csi.ControllerServer. Like nodeService it is a
// field of Driver, not embedded (testEmbeddedByValue ambiguity).
type controllerService struct {
	csi.UnimplementedControllerServer
	driver *Driver
	// locks rejects concurrent operations on the same volume name or id; the
	// RPCs that need it arrive with T-11.
	locks lockTable
}
```
- `ControllerGetCapabilities`：只返回 `SINGLE_NODE_MULTI_WRITER`（D-23；列表放在一个包级变量里，顺序固定）。
- 其它 Controller RPC 保持 `Unimplemented`（由 `UnimplementedControllerServer` 提供）。

`ValidateVolumeCapabilities(ctx, req)`，按以下顺序：
1. `volume_id` 为空 → `InvalidArgument`；`volume_capabilities` 为空 → `InvalidArgument`。
2. 每个 capability 调 `checkControllerCapability`，`err != nil`（畸形）→ 原样返回（`InvalidArgument`）。
3. `ctx` 已取消 → 用现有的 `ctxStatus(ctx)`。
4. `decodeVolumeID`（畸形 id → `NotFound`，与 Node 侧一致）；`clusterID` 不在当前配置 → `NotFound`（"volume %s not found: cluster %q is not configured"）。
5. 逐项判断是否支持，第一个不支持的原因写进 `Message`，`Confirmed` 为 nil，返回 OK（**不是**错误，CSI 规范要求）：
   - 不支持的 capability（第 2 步记下的 reason）；
   - 每个 Mount capability 的 `mount_flags`：用 `mounter.BuildMountArgs(mounter.Spec{Servers: 集群的 servers, Volume: id.Volume, Subdir: id.Subdir, Options: flags}, "")`
     试构造，出错 → 不支持（原因带上错误）。这样 Node 会拒绝的 mountOptions 在这里就能发现；
   - `parameters` 非空时：`parseVolumeParameters` 失败 → 不支持；成功但与卷不符 → 不支持：id 的 mode 不是参数的 mode、
     `ClusterID` 不同、`ParentVolume` 不等于 `id.Volume`；
   - `mutable_parameters` 非空 → 不支持（"mutable parameters are not supported"，未声明 MODIFY_VOLUME）；
   - `volume_context` 中出现 `clusterID`、`volume`、`subdir` 这三个 key 时，值必须与 id 一致（`subdir` 对没有子目录的 id 必须不存在或为空），
     否则不支持；其它 key 忽略（volume_context 只是信息，Node 侧只信 volume_id）。
6. 全部支持 → `Confirmed{VolumeContext, VolumeCapabilities, Parameters, MutableParameters}` 原样回显请求中的值（复制 map/slice，不共享请求内存）。

不持锁（只读，不修改任何东西）。日志：拦截器已经记录每个 RPC；这里只在不支持时 `klog.V(4)` 记原因。

## 测试（表驱动，断言行为）
1. `TestParseVolumeParameters`：最小合法（clusterID + parentVolume）→ 缺省 mode subdir、onDelete delete；三个 onDelete 值；`quota: "false"`；
   `csi.storage.k8s.io/pvc/name` 等前缀 key 被忽略；缺 clusterID；缺 parentVolume；`clusterID: ""`；非法字符（`a/b`、`..`、空格、超长）；
   `provisioningMode` 为 static、volume、`Subdir`（大小写）；`onDelete: Delete`；`quota: "true"`、`quota: "yes"`；未知 key `clusterid`、`foo`；
   多个错误同时存在 → 消息包含每一个，且两次调用消息完全相同；所有错误 `errors.Is(err, errInvalidParameters)`；超长值不被回显。
2. `TestCheckControllerCapability`：每个已定义访问模式 + Mount → supported；fs_type `glusterfs` 与空 → supported；Block → 不支持；
   fs_type `ext4` → 不支持；nil / 无 mode / UNKNOWN / 99 / 无 access type → `InvalidArgument`。`validateNodeCapability` 的现有测试继续通过。
3. `TestControllerGetCapabilities`：恰好一个 RPC 能力 `SINGLE_NODE_MULTI_WRITER`，不含 `CREATE_DELETE_VOLUME`。
4. `TestValidateVolumeCapabilities`（用 `testConfigStore` 配一个 cluster）：
   - static 与 subdir id、多个 capability → Confirmed，且回显的 VolumeContext/Parameters/Capabilities 与请求相等；
   - 空 volume_id、空 capabilities、畸形 capability → `InvalidArgument`；畸形 capability 与不存在的卷同时出现 → `InvalidArgument`（顺序）；
   - id 无法解码（如 `some-vol-id`）、cluster 不在配置 → `NotFound`；
   - Block、`ext4` → OK 且 `Confirmed == nil`、`Message` 非空；
   - 非法 mount flag（如 `rw` 或不在白名单的 `foo=bar`）→ 未确认；合法 flag（`log-level=WARNING`）→ 确认；
   - parameters：合法且匹配 → 确认；未知 key、`quota: "true"`、clusterID 不同、parentVolume 不同、static id 配 subdir 参数 → 未确认；
   - mutable_parameters 非空 → 未确认；
   - volume_context：`volume` 与 id 不符、对无子目录的 id 给出非空 `subdir` → 未确认；只有无关 key → 确认；
   - ctx 已取消 → 现有 `ctxStatus` 的错误码；
   - 修改返回的 Confirmed 中的 map 不影响请求（不共享内存）。
5. `driver_test.go`：controller 与 all 模式没有 Config → New 报错；controller 模式 `controllerRegistered` 为 true、`node` 为 nil；
   node 模式 `controller` 为 nil。`identity_test.go`：controller/all 模式声明 `CONTROLLER_SERVICE`，node 模式不声明。
6. 端到端（`server_test.go` 或 `driver_test.go` 已有的 bufconn 方式）：controller 模式的 Driver 上 `ControllerGetCapabilities` 与
   `ValidateVolumeCapabilities` 可调用；`CreateVolume` 返回 `Unimplemented`；node 模式调用 Controller RPC 返回 `Unimplemented`（服务未注册）。
