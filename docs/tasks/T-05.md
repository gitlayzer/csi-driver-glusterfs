## 背景
架构 §5.3：NodeStage 在 staging 路径做一次 FUSE 挂载（`mount -t glusterfs`），NodePublish 只做 bind mount。
挂载参数固定包含 `backup-volfile-servers=<其余 servers>`、`log-level=WARNING`（可被用户覆盖）、
`log-file=<logDir>/<name>.log`，以及 StorageClass `mountOptions` 的**白名单**透传。
本包只负责“算参数 + 幂等地挂/卸”，不知道 CSI，也不返回 gRPC status；错误用哨兵值表达，由 T-06 映射成 CSI 错误码。

## 设计

### `pkg/mounter/options.go`

```go
// Spec describes one GlusterFS FUSE mount.
type Spec struct {
	Servers  []string // 至少 1 个；Servers[0] 是主 volfile server，其余进 backup-volfile-servers
	Volume   string   // gluster 卷名
	Subdir   string   // 可选，子目录挂载（gluster 原生 subdir mount：server:/vol/subdir）
	ReadOnly bool
	Options  []string // StorageClass mountOptions / PV mountOptions 原样传入，每项可能含逗号
}

// FSType is passed to mount(8); /proc/mounts reports it as "fuse.glusterfs".
const FSType = "glusterfs"

// DefaultLogLevel is used unless Spec.Options sets log-level.
const DefaultLogLevel = "WARNING"

var (
	ErrInvalidSpec   = errors.New("invalid mount spec")   // Servers/Volume/Subdir 非法
	ErrInvalidOption = errors.New("invalid mount option") // 不在白名单 / 值非法 / 重复
)

// BuildMountArgs validates spec and returns the mount(8) source and option list.
// logDir 为空时不加 log-file。
func BuildMountArgs(spec Spec, logDir string) (source string, options []string, err error)
```

**校验**（全部失败都 `fmt.Errorf("...: %w", ErrInvalidSpec)`，信息里给出字段名，超长值不回显原文）：
- `Servers` 非空，最多 32 个（与 `config.MaxServers` 一致，可直接引用 `config.MaxServers`）；每个 server 非空、
  不含空白、不含 `:`（IPv6 无法放进以 `:` 分隔的 backup-volfile-servers，本期明确不支持，错误信息写明）、`,`、`/`、`=`，
  不以 `-` 开头，长度 ≤ 253；按大小写不敏感去重（重复 → 错误）。
- `Volume` 用 `volumeid.ValidateName("volume", ...)`；`Subdir` 非空时用 `volumeid.ValidateName("subdir", ...)`
  （它已经拒绝 `.`、`..`、`/`）。
- `logDir` 非空时必须是绝对路径且 `filepath.Clean(logDir) == logDir`，否则 `ErrInvalidSpec`。

**source**：`Servers[0] + ":/" + Volume`，有 Subdir 时再加 `"/" + Subdir`。

**options**（顺序固定，测试按完整切片断言）：
1. 用户选项：`Spec.Options` 每一项按 `,` 拆分，**逐个**按下表校验，保持原顺序。空片段（`"a,,b"`、`""`、首尾逗号）→
   `ErrInvalidOption`。同一个 key 出现两次（不论值是否相同，例如 `acl,acl` 或 `log-level=INFO,log-level=DEBUG`）→ `ErrInvalidOption`。
2. `ReadOnly` 为 true 且用户选项里没有 `ro` 时追加 `ro`。
3. 用户选项里没有 `log-level` 时追加 `log-level=WARNING`。
4. `len(Servers) > 1` 时追加 `backup-volfile-servers=` + `strings.Join(Servers[1:], ":")`。
5. `logDir` 非空时追加 `log-file=` + `filepath.Join(logDir, name)`，`name` 为 `<volume>.log`，有 Subdir 时为
   `<volume>_<subdir>.log`（下划线拼接在极少数情况下会让两个挂载共用一个日志文件，可接受；在注释里写明）。

**mountOptions 白名单**（key 大小写敏感，与 mount.glusterfs 一致）：

| 类别 | key | 值规则 |
|---|---|---|
| 开关（不得带 `=`） | `ro`、`acl`、`selinux`、`auto_unmount`、`fopen-keep-cache`、`enable-ino32` | 带 `=` → 错误 |
| 枚举 | `log-level` | `CRITICAL` `ERROR` `WARNING` `INFO` `DEBUG` `TRACE` `NONE` |
| 枚举 | `use-readdirp`、`kernel-writeback-cache` | `yes` `no` |
| 枚举 | `direct-io-mode` | `enable` `disable` |
| 小数秒 | `attribute-timeout`、`entry-timeout`、`negative-timeout`、`gid-timeout` | `^[0-9]{1,6}(\.[0-9]{1,3})?$` |
| 非负整数 | `background-qlen`、`congestion-threshold`、`reader-thread-count`、`lru-limit`、`invalidate-limit` | `^[0-9]{1,9}$` |
| **禁止**（驱动自己控制或可逃逸） | `log-file`、`backup-volfile-servers`、`backupvolfile-server`、`volfile-server`、`volfile-id`、`xlator-option`、`fuse-mountopts`、`process-name`、`transport`、`rw` | 一律错误，信息写明“controlled by the driver”或“not allowed” |
| 其他任何 key | — | 错误（白名单之外） |

带值的 key 缺 `=` 或值为空 → 错误。错误信息可以回显 option（已知 ≤ 合理长度时）；
单个片段超过 256 字节 → 直接报错且不回显原文（只报长度）。

### `pkg/mounter/mounter.go`

```go
var (
	// ErrMountConflict: target 已经挂着别的东西（不同的卷/子目录/文件系统类型/只读属性）。
	// T-06 映射为 AlreadyExists。
	ErrMountConflict = errors.New("target is already mounted with a different source or flags")
	// ErrCorruptedMount: target 是一个已损坏的挂载点（ENOTCONN 等，FUSE 进程已退出）。
	// T-06 / 恢复器（T-08）据此决定先 Unmount 再重挂。
	ErrCorruptedMount = errors.New("target is a corrupted mount point")
)

// Mounter mounts and unmounts GlusterFS volumes. 所有方法幂等。
type Mounter interface {
	// MountGlusterfs FUSE-mounts spec at target (NodeStage).
	MountGlusterfs(ctx context.Context, spec Spec, target string) error
	// BindMount bind-mounts source at target, read-only if readOnly (NodePublish).
	BindMount(ctx context.Context, source, target string, readOnly bool) error
	// Unmount unmounts target if it is mounted (including corrupted mounts) and keeps the directory (NodeUnstage).
	Unmount(ctx context.Context, target string) error
	// Cleanup unmounts target if mounted and then removes the directory (NodeUnpublish：CSI 规定 SP 删除自己在 target_path 创建的目录).
	Cleanup(ctx context.Context, target string) error
	// IsMountPoint reports whether target is a mount point. 损坏的挂载点返回 (false, 包装了 ErrCorruptedMount 的 error)。
	IsMountPoint(target string) (bool, error)
}

// New returns a Mounter backed by m（生产用 mount.New("")，测试用 mount.NewFakeMounter）。
// logDir 原样交给 BuildMountArgs；New 本身不做 I/O。
func New(m mount.Interface, logDir string) Mounter
```

**共同规则**
- 每个修改性方法开头 `if err := ctx.Err(); err != nil { return err }`（mount-utils 不支持 ctx，原样返回 ctx 错误，
  T-06 用 `status.FromContextError` 映射）。
- `target`、`source` 必须是非空绝对路径且已经 `filepath.Clean` → 否则返回包装 `ErrInvalidSpec` 的错误。
- 挂载点判断统一用 `m.IsMountPoint(target)`（能识别同一文件系统内的 bind mount），**不要**用 `IsLikelyNotMountPoint`。
- **损坏判断** `isCorrupted(err)`：`mount.IsCorruptedMnt(err)` 为真，**或** `errors.Is(err, e)` 对
  `syscall.ENOTCONN`、`ESTALE`、`EIO`、`EHOSTDOWN`、`EACCES`、`EWOULDBLOCK` 任一为真
  （`IsCorruptedMnt` 只看最外层类型，不认 `fmt.Errorf("%w")` 包装过的错误）。
- 查找已有挂载条目：`m.List()` 中 `Path` 等于 `target` 或 `filepath.EvalSymlinks(target)` 的条目，取**最后一条**
  （同一路径叠挂时最上层在后）。
- 所有返回的错误都带上 target（不含任何 Secret；本包也不接触 Secret）。
- 日志：挂载/卸载成功 `klog.V(2).InfoS`（字段 source、target、options），跳过（已挂载）`klog.V(4).InfoS`。
  options 里没有敏感内容，可以记录。

**MountGlusterfs**
1. `BuildMountArgs(spec, logDir)`；错误原样返回（`ErrInvalidSpec` / `ErrInvalidOption`）。
2. `IsMountPoint(target)`：
   - `os.IsNotExist` → 返回错误（`target %q does not exist`，包装原错误；创建目录是 T-06 的事）。
   - 损坏 → 返回包装 `ErrCorruptedMount` 的错误，**不要**自动卸载（交给调用方决定）。
   - 其他错误 → 包装返回。
3. 已是挂载点：找到条目，满足**全部**以下条件则视为同一挂载，返回 nil（不再调用 Mount）：
   - `Type` 为 `glusterfs` 或 `fuse.glusterfs`；
   - `Device` 中第一个 `:` 之后的部分等于 source 中第一个 `:` 之后的部分（只比较 `/vol[/subdir]`，因为实际连上的
     volfile server 可能是任一 backup）；
   - `Opts` 是否包含 `ro` 与 options 是否包含 `ro` 一致。
   否则返回包装 `ErrMountConflict` 的错误，信息中说明现有的 device/type。找不到条目（IsMountPoint 说是但 List 里没有）
   也按冲突处理。
4. 未挂载：`m.Mount(source, target, FSType, options)`；失败包装返回（`mount glusterfs %s at %s: %w`）。

**BindMount**
1. 校验 source、target；`IsMountPoint(target)` 的处理同上（不存在 → 错误；损坏 → `ErrCorruptedMount`）。
2. 已是挂载点：找到条目，`Opts` 是否含 `ro` 与 `readOnly` 一致 → nil；不一致或找不到条目 → `ErrMountConflict`。
   （bind mount 在 /proc/mounts 里显示的是原设备，不比较 device。）
3. 未挂载：options 为 `["bind"]`，`readOnly` 时为 `["bind", "ro"]`，调用 `m.Mount(source, target, "", options)`
   （mount-utils 在 Linux 上会把 `bind,ro` 拆成 bind + remount,ro 两步）。

**Unmount / Cleanup**（共用一个内部函数，`removeDir` 区分）
1. 校验 target；`IsMountPoint(target)`：
   - `os.IsNotExist` → 返回 nil（幂等）。
   - 损坏 → 直接 `m.Unmount(target)`（损坏的 FUSE 挂载点必须能被卸载，这是恢复路径）。
   - 其他错误 → 包装返回。
   - 是挂载点 → `m.Unmount(target)`。
   - 不是挂载点 → 跳过卸载。
2. `removeDir` 为 true 时 `os.Remove(target)`，`os.IsNotExist` 视为成功；目录非空等其他错误包装返回
   （**不得**用 `os.RemoveAll`，非空说明卸载没成功或有人写了数据）。
3. 不使用 `mount.CleanupMountPoint`：它总是删除目录，而 staging 目录归 kubelet 所有。

**IsMountPoint**：调用 `m.IsMountPoint`；损坏 → `(false, 包装 ErrCorruptedMount 的 error)`；其他错误原样（包装）返回。
T-07 的 `NodeGetVolumeStats` 会用它上报 `VOLUME_CONDITION`。

## 测试（表驱动，断言行为）
测试中 target 目录用 `t.TempDir()` 创建（FakeMounter 的 IsMountPoint 会 `os.Stat`）。macOS 上 TempDir 在 `/var`→`/private/var`
符号链接下，FakeMounter 记录的是 EvalSymlinks 后的路径，查找条目时务必按“共同规则”同时匹配两种路径。

1. `TestBuildMountArgs`（至少下列用例，按完整 source 与完整 options 切片断言）：
   - 单 server 无 subdir：`10.0.0.1:/vol`，`[log-level=WARNING]`（logDir 为空）；
   - 三 server + subdir + logDir `/var/log/glusterfs/csi`：source `g1:/vol/pvc-1`，options 末尾依次为
     `log-level=WARNING`、`backup-volfile-servers=g2:g3`、`log-file=/var/log/glusterfs/csi/vol_pvc-1.log`；
   - ReadOnly：追加 `ro`；ReadOnly 且用户已给 `ro`：只出现一次；
   - 用户 `log-level=DEBUG`：不再追加默认 log-level；
   - `Options: ["acl,use-readdirp=no", "attribute-timeout=0.5"]` → 拆分后原顺序保留；
   - 非法：Servers 为空、33 个、含 `:`（`::1`）、含 `,`、含空格、以 `-` 开头、大小写重复（`G1`/`g1`）、Volume 为 `..`、
     Subdir 为 `a/b`、logDir 为相对路径或 `/a/../b` —— 全部 `errors.Is(err, ErrInvalidSpec)`；
   - 非法选项：`log-file=/x`、`backup-volfile-servers=a`、`xlator-option=a.b=c`、`rw`、`foo`、`acl=1`、`log-level=LOUD`、
     `log-level=`、`attribute-timeout=abc`、`attribute-timeout=1.2345`、`lru-limit=-1`、`a,,b`、`""`、`acl,acl`、
     `log-level=INFO,log-level=DEBUG`、300 字节的片段 —— 全部 `errors.Is(err, ErrInvalidOption)`；
     300 字节用例额外断言错误信息不含原文。
2. `TestMountGlusterfs`（`mount.NewFakeMounter(nil)`）：
   - 首次挂载：FakeMounter 的 `GetLog()` 有且仅有一次 mount，source/fstype 正确，`MountPoints` 中 Opts 等于 BuildMountArgs 结果；
   - 再次调用相同 spec：返回 nil，`GetLog()` 仍只有一次 mount（幂等）；
   - 已挂载 `fuse.glusterfs` 类型、device 为 **另一个 server** 但同一 `/vol` → 视为相同，nil；
   - 已挂载不同卷 / 不同 subdir / `nfs` 类型 / ro 不一致 → `errors.Is(err, ErrMountConflict)`；
   - `MountCheckErrors[target] = syscall.ENOTCONN` → `errors.Is(err, ErrCorruptedMount)` 且没有调用 Mount/Unmount；
   - 用 `&os.PathError{Op: "stat", Path: target, Err: syscall.ENOTCONN}` 以及 `fmt.Errorf("x: %w", syscall.ESTALE)` 注入，同样识别为损坏；
   - target 不存在 → 错误且非 ErrCorruptedMount；
   - 非法 spec → ErrInvalidSpec，且没有调用 Mount；
   - ctx 已取消 → `errors.Is(err, context.Canceled)`，没有调用 Mount；
   - 相对路径 target → ErrInvalidSpec。
   - 注入 Mount 失败：用一个嵌入 `*mount.FakeMounter` 并覆盖 `Mount` 返回错误的测试类型，断言错误被包装返回且信息含 target。
3. `TestBindMount`：rw / ro 首次挂载的 options（`[bind]` / `[bind ro]`）；重复调用幂等（只一次 mount）；ro 不一致 → ErrMountConflict；
   损坏 → ErrCorruptedMount；ctx 取消；source 为相对路径 → ErrInvalidSpec。
4. `TestUnmountAndCleanup`：
   - 已挂载：Unmount 后不再是挂载点、目录仍存在；Cleanup 后目录被删除；
   - 再次调用都返回 nil（幂等），目录不存在时也返回 nil；
   - 未挂载的空目录：Unmount 不调用 FakeMounter.Unmount、目录保留；Cleanup 删除目录；
   - 损坏（ENOTCONN）：Unmount 会调用 FakeMounter.Unmount（`GetLog()` 断言有一次 unmount 动作），之后 IsMountPoint 不再报损坏；
   - 未挂载但目录非空：Cleanup 返回错误且目录与其中文件仍存在；
   - Unmount 失败（`UnmountFunc` 返回错误）→ 错误被包装返回，Cleanup 不删除目录。
5. `TestIsMountPoint`：挂载 / 未挂载 / 损坏（返回 false + ErrCorruptedMount）/ 不存在（错误满足 `os.IsNotExist` 或 `errors.Is(err, fs.ErrNotExist)`）。
