## 目标
node / all 模式注册 CSI **Node** 服务。NodeStage 把 GlusterFS 卷 FUSE 挂载到 staging 路径（每节点每卷一个 FUSE 进程），
NodePublish 把 staging 路径 bind mount 到 Pod 的 target 路径。所有 RPC 幂等，错误码严格按 CSI v1.13 规范与 AGENTS.md 错误码表
（**注意 AGENTS.md 已按 D-16 更新：Node 侧“不支持的能力”是 FailedPrecondition**）。

本任务**不实现** `NodeGetVolumeStats`（T-07）、`NodeExpandVolume`（不需要），二者由 `csi.UnimplementedNodeServer` 返回 Unimplemented，
能力列表中也**不得**声明 `GET_VOLUME_STATS`、`VOLUME_CONDITION`、`EXPAND_VOLUME`。

### `pkg/driver/inflight.go`
```go
// inflight is a set of keys of operations in progress. tryAcquire never blocks:
// a concurrent operation on the same key is rejected with Aborted, as the CSI spec requires.
type inflight struct { mu sync.Mutex; keys map[string]struct{} }
func newInflight() *inflight
func (l *inflight) tryAcquire(key string) bool
func (l *inflight) release(key string)
```
- 键：Stage / Unstage 用 `"stage/" + volume_id`；Publish / Unpublish 用 `"publish/" + target_path`
  （同一卷在同一节点给多个 Pod 发布时互不阻塞）。
- 获取失败 → `codes.Aborted`，信息 `an operation on %s is already in progress`（%s 为 volume id 或 target path）。
- 必须 `defer release`；锁在**参数校验之后**获取（否则 InvalidArgument 会被 Aborted 掩盖）。T-10 会复用这个类型。

### `pkg/driver/capability.go`
```go
// nodeCapability is what a validated VolumeCapability means for the node service.
type nodeCapability struct {
	readOnly   bool     // access mode is SINGLE_NODE_READER_ONLY or MULTI_NODE_READER_ONLY
	mountFlags []string // VolumeCapability.Mount.MountFlags, passed to the mounter unchanged (it validates them)
}
// validateNodeCapability returns a gRPC status error on failure.
func validateNodeCapability(c *csi.VolumeCapability) (nodeCapability, error)
```
规则（按顺序）：
| 情况 | 结果 |
|---|---|
| `c == nil` | `InvalidArgument`（`volume capability is required`） |
| `AccessMode == nil` 或 `Mode == UNKNOWN` | `InvalidArgument` |
| Mode 不是 csi.proto 中已定义的 7 个非 UNKNOWN 值之一（例如 99） | `InvalidArgument` |
| `AccessType == nil` | `InvalidArgument` |
| `AccessType` 是 Block | `FailedPrecondition`（`block access type is not supported`） |
| Mount 的 `FsType` 不是 `""` 也不是 `glusterfs` | `FailedPrecondition` |
| 其余 | 通过 |

7 个访问模式全部支持：GlusterFS 卷天然 RWX；RWOP/RWO 的单 Pod / 单节点约束由 CO 保证，Node 无需额外处理。
只读模式（`SINGLE_NODE_READER_ONLY`、`MULTI_NODE_READER_ONLY`）→ `readOnly = true`。

### `pkg/driver/node.go`
```go
type nodeService struct {
	csi.UnimplementedNodeServer
	driver  *Driver
	mounter mounter.Mounter // tests replace it
	logDir  string
	locks   *inflight
}
```
**公共校验** `validatePath(field, p string) error`（返回 gRPC status）：非空由各 RPC 先检查；必须是绝对路径且
`filepath.Clean(p) == p`（拒绝 `..`、`//`、末尾 `/`），否则 `InvalidArgument`。
**volume_id 解码**：`volumeid.Decode` 失败 → `NotFound`（`volume %q not found: %v`，volume id 超过 128 字节时不回显原文，只报长度）。

**错误映射** `mountErrorToStatus(op string, err error) error`：
| mounter 错误 | gRPC code |
|---|---|
| `context.Canceled` / `DeadlineExceeded` | `status.FromContextError(err)` |
| `mounter.ErrInvalidSpec` / `mounter.ErrInvalidOption` | `InvalidArgument` |
| `mounter.ErrMountConflict` | `AlreadyExists` |
| 其他（含 `ErrCorruptedMount`） | `Internal`（`%s: %v`，op 如 `"stage volume"`） |

#### NodeStageVolume
1. `volume_id` 空 → InvalidArgument；`staging_target_path` 空 → InvalidArgument；`validatePath`；`validateNodeCapability`。
2. Decode volume_id → 失败 NotFound。
3. `locks.tryAcquire("stage/"+id)` → Aborted。
4. `cluster, ok := driver.config.Current().Get(id.ClusterID)`；`!ok` → `NotFound`（`cluster %q of volume %q is not configured`）。
5. `logDir` 非空时 `os.MkdirAll(logDir, 0o755)`，失败 → Internal。
6. staging 路径不存在时 `os.MkdirAll(staging, 0o750)`（规范要求 CO 创建，但自建无害且更健壮），失败 → Internal。
7. `spec := mounter.Spec{Servers: cluster.Servers, Volume: id.Volume, Subdir: id.Subdir, ReadOnly: cap.readOnly, Options: cap.mountFlags}`。
8. `MountGlusterfs(ctx, spec, staging)`：
   - `ErrCorruptedMount`（上一次的 FUSE 进程已死）→ `klog.InfoS` 记录后 `Unmount(ctx, staging)` 再 **重试一次** `MountGlusterfs`；
     Unmount 失败或重试仍失败按错误映射返回。不得无限重试。
   - 其他错误按错误映射。
9. `volume_context`、`publish_context`、`secrets` **忽略**（volume_id 是唯一事实来源，注释写明；Secrets 绝不记录）。

#### NodeUnstageVolume
1. `volume_id` 空、`staging_target_path` 空 → InvalidArgument；`validatePath`。
2. Decode → NotFound。**不**查 config（集群配置被删掉后也必须能卸载）。
3. 锁 `"stage/"+id`。
4. `mounter.Unmount(ctx, staging)`（保留目录）→ 错误映射。已经卸载 / 目录不存在 → OK（mounter 已保证）。

#### NodePublishVolume
1. `volume_id` 空 → InvalidArgument；`target_path` 空 → InvalidArgument；`volume_capability` nil → InvalidArgument；
   `staging_target_path` 空 → **FailedPrecondition**（规范 "Staging target path not set"）。两个路径 `validatePath`；`validateNodeCapability`。
2. Decode → NotFound。
3. 锁 `"publish/"+target`。
4. `mounted, err := mounter.IsMountPoint(staging)`：
   - `errors.Is(err, fs.ErrNotExist)` 或 `!mounted` → **FailedPrecondition**（`volume %q is not staged at %q`）；
   - `ErrCorruptedMount` → Internal（`staging mount of volume %q is corrupted`；恢复由 T-08 负责）；
   - 其他错误 → Internal。
5. `readOnly := req.Readonly || cap.readOnly`。
6. `os.MkdirAll(target, 0o750)`（规范：“Creation of target_path is the responsibility of the SP”）→ 失败 Internal。
7. `BindMount(ctx, staging, target, readOnly)`：`ErrCorruptedMount` → `Unmount(ctx, target)` 后重试一次（同 Stage）；其他按错误映射
   （`ErrMountConflict` → AlreadyExists，即规范的 “Volume published but is incompatible”）。

#### NodeUnpublishVolume
1. `volume_id` 空、`target_path` 空 → InvalidArgument；`validatePath`。
2. Decode → NotFound。
3. 锁 `"publish/"+target`。
4. `mounter.Cleanup(ctx, target)`（卸载并删除目录，规范要求 SP 删除自己创建的 target）→ 错误映射。

#### NodeGetCapabilities
返回且只返回 `STAGE_UNSTAGE_VOLUME`、`SINGLE_NODE_MULTI_WRITER`（RPC 类型），顺序固定。

#### NodeGetInfo
`NodeId = driver.nodeID`，`MaxVolumesPerNode = 0`（不限制），不返回 `AccessibleTopology`（架构 §5.4 不声明拓扑）。

### `cmd/glusterfs-csi/main.go`
- 新 flag `--mount-log-dir`，默认 `/var/log/glusterfs/csi`，帮助文本说明空字符串表示不写 log-file。
- `validateFlags` 校验：非空时必须是绝对且干净的路径（错误前缀 `invalid --mount-log-dir:`）。

## 测试（表驱动，断言行为）
测试替身：
- `fakeMounter`（在 `node_test.go`）：实现 `mounter.Mounter`，按方法记录调用次数与参数，每个方法可注入一串依次返回的错误
  （用于“第一次 ErrCorruptedMount、第二次成功”的重试用例）。
- 端到端用例使用真实 `mounter.New(mount.NewFakeMounter(nil), "")`，路径用 `t.TempDir()`，验证幂等与目录行为。
- 测试中的 config：辅助函数写临时 JSON（集群 `c1`，servers `g1,g2,g3`）并 `config.NewStore`。

1. `TestValidateNodeCapability`：nil；无 AccessMode；UNKNOWN；Mode=99；无 AccessType；Block → FailedPrecondition；
   FsType `ext4` → FailedPrecondition；FsType `""` 与 `glusterfs` 通过；7 个访问模式逐一通过，且只读模式 `readOnly=true`、其余 false；
   mountFlags 原样返回。断言 `status.Code`。
2. `TestInflight`：同 key 第二次 tryAcquire 为 false，release 后为 true；不同 key 互不影响；`-race` 下 50 个 goroutine 并发
   tryAcquire 同一 key 只有 1 个成功。
3. `TestNodeStageVolume`（fakeMounter）：
   - 缺 volume_id / staging / capability → InvalidArgument；相对路径与 `/a/../b` → InvalidArgument；
   - Block → FailedPrecondition；volume_id `garbage` → NotFound；clusterID 不在配置中 → NotFound；
   - 成功：MountGlusterfs 收到的 Spec 为 `{Servers:[g1 g2 g3], Volume, Subdir, ReadOnly, Options: mountFlags}`、target 为 staging；
   - `MULTI_NODE_READER_ONLY` → Spec.ReadOnly 为 true；
   - staging 不存在 → 被创建；logDir（临时目录下的子目录）被创建；
   - mounter 返回 ErrInvalidOption → InvalidArgument；ErrMountConflict → AlreadyExists；普通错误 → Internal；
   - 第一次 ErrCorruptedMount、第二次 nil → OK，且 Unmount 调用 1 次、MountGlusterfs 调用 2 次；
     两次都 ErrCorruptedMount → Internal 且 MountGlusterfs 恰好 2 次；
   - ctx 已取消（mounter 返回 ctx.Err()）→ Canceled；
   - 已持有 `stage/<id>` 锁时 → Aborted，且未调用 mounter；
   - 请求带 Secrets 时，不论成败，Secrets 的值都不出现在返回的错误信息里。
4. `TestNodeUnstageVolume`：缺字段 → InvalidArgument；garbage id → NotFound；clusterID 未配置**也成功**（不查 config）；
   调用 Unmount（不是 Cleanup）；Unmount 错误 → Internal；锁冲突 → Aborted。
5. `TestNodePublishVolume`：缺 volume_id / target / capability → InvalidArgument；缺 staging → FailedPrecondition；
   staging 不是挂载点 / 不存在 → FailedPrecondition；staging 损坏 → Internal；`Readonly=true` 或 `SINGLE_NODE_READER_ONLY`
   → BindMount readOnly=true；target 不存在 → 被创建；ErrMountConflict → AlreadyExists；BindMount 损坏重试一次；锁冲突 → Aborted。
6. `TestNodeUnpublishVolume`：缺字段 → InvalidArgument；garbage id → NotFound；调用 Cleanup；错误 → Internal。
7. `TestNodeLifecycle`（真实 mounter + FakeMounter，经 bufconn 起 gRPC server、`csi.NewNodeClient` 调用）：
   Stage → Stage（幂等）→ Publish → Publish（幂等）→ 用 readonly 相反的参数 Publish → AlreadyExists → Unpublish（target 目录被删）
   → Unpublish（幂等）→ Unstage（staging 目录仍在）→ Unstage（幂等）。断言 FakeMounter 的 `GetLog()` 中 mount/unmount 次数。
8. `TestNodeGetCapabilities`、`TestNodeGetInfo`：精确断言能力集合与 NodeId；`NodeGetVolumeStats`、`NodeExpandVolume` 返回 Unimplemented。
9. `TestNew` 补充：node/all 模式缺 Config → 错误；MountLogDir 为相对路径 / 不干净 → 错误；controller 模式不注册 Node 服务
   （经 bufconn 调用 `NodeGetInfo` 返回 Unimplemented）。
10. main_test：`--mount-log-dir=relative` 与 `--mount-log-dir=/a/../b` 被拒；空字符串被接受。
