## 背景（必读）

M3 的配额、扩容和 volume 模式要在 Gluster 节点上执行 `gluster` 管理命令（D-34）。驱动不在本地装 gluster CLI，而是通过 SSH
登录任一 Gluster 节点执行；任一 glusterd 都能执行集群级管理命令，所以一台不可达时换下一台（按 ConfigMap 中 `servers` 的顺序）。

本任务只做通道本身：把一条 argv 安全地送到远端执行、拿回 stdout / 退出码，以及在多台主机之间故障转移。
gluster 命令的封装与 XML 解析是 T-16；凭据从哪里来（CSI 请求的 secrets 还是 controller 挂载的 Secret）是 T-17 的决策，
本任务只把“一份 Secret 的数据”解析成凭据，与来源无关。

用户已决定（D-34）：
1. **主机密钥强制校验**：凭据里必须有 `known_hosts`，对不上就拒绝连接；没有任何关闭校验的开关，没有 TOFU。
2. **每次调用新建连接**：不做连接池，没有后台 goroutine。
3. **驱动不提权**：只发 argv 本身（如 `gluster --mode=script --xml volume info`），不加 `sudo`；非 root 账号的提权由 T-19 的 wrapper 负责。
4. **凭据来源留给 T-17**。

安全要求（AGENTS.md）：远端命令行由本包把**每个参数**单独 shell-quote 后拼接，绝不把未经 quote 的字符串送到远端；
私钥、Secret 内容绝不出现在日志和错误消息里。

### `executor.go`
```go
// Executor runs a command on one GlusterFS server.
type Executor interface {
    // Run runs args (args[0] is the program) on host and returns its stdout.
    Run(ctx context.Context, host string, args ...string) ([]byte, error)
}
```
签名与 architecture §5.2 相同。

错误：
- `var ErrConnect = errors.New("cannot reach the glusterfs server")`：**远端命令开始执行之前**的所有失败都包装它——解析主机名、
  TCP 连接、SSH 握手、主机密钥不在 / 不匹配 known_hosts、认证失败、打开 session、exec 请求被拒绝。
  包装它就保证远端什么都没执行，故障转移只看这个（见 `failover.go`）。
- `var ErrInvalidCommand = errors.New("invalid executor command")`：命令校验失败，不联网。
- `type ExitError struct { Host string; Program string; Code int; Stderr []byte }`：远端命令已执行并以非零状态退出。
  `Error()` 形如 `gluster on gluster-1 exited with status 1: <stderr>`，stderr 去掉首尾空白、控制字符换成空格、
  超过 256 字节截断并加 `...`；`Stderr` 字段最多保留 64 KiB。
- 远端命令开始后连接断开、没有退出状态（`*ssh.ExitMissingError`）、输出超限等：返回带主机名的普通错误，**不**包装 `ErrConnect`。
- ctx 取消或超时：返回的错误满足 `errors.Is(err, ctx.Err())`。开始执行之前取消也**不**包装 `ErrConnect`（取消不是主机故障）：
  连接 / 握手阶段失败时先看 `ctx.Err()`，非空就返回 ctx 的错误，否则才包装 `ErrConnect`（`DialTimeout` 到期属于后者）。

命令校验 `validateCommand(host string, args []string) error`（在联网前执行，失败包装 `ErrInvalidCommand`）：
- `host` 非空，不含空白、控制字符、`@`、`/`；不做主机名语法校验（servers 已由 `pkg/config` 校验）。
- `len(args) >= 1`；`args[0]` 必须在允许的程序列表中，目前只有 `gluster`（`var allowedPrograms = map[string]bool{"gluster": true}`，
  M4 加 lvm 命令时再扩充）。
- 任何参数不得包含 ASCII 控制字符（`0x00–0x1f`、`0x7f`），且必须是合法 UTF-8；参数可以为空字符串。
- quote 后的整条命令不超过 64 KiB。

### `quote.go`
```go
// shellQuote returns args as one POSIX shell command line in which every
// argument is a single-quoted word.
func shellQuote(args []string) string
```
每个参数都加单引号（包括不含特殊字符的参数，规则统一，便于 T-19 的 wrapper 解析）：`'` + 把参数中的 `'` 替换为 `'\''` + `'`，
参数之间用一个空格连接。空字符串得到 `''`。远端账号的登录 shell 必须是 POSIX 兼容的（bash/dash/zsh/sh），或者由
`authorized_keys` 的 `command=` 指定 wrapper（T-19）；写进 `doc.go`。

### `credentials.go`
```go
type Credentials struct {
    User string
    Port int                          // 默认 22
    signer          ssh.Signer
    hostKeyCallback ssh.HostKeyCallback
    hostKeyAlgorithms []string
}

// ParseCredentials parses the data of an SSH Secret.
func ParseCredentials(data map[string]string) (*Credentials, error)
```
`data` 的键（与 Kubernetes `kubernetes.io/ssh-auth` 类型 Secret 兼容，多出的键忽略）：

| 键 | 必填 | 规则 |
|---|---|---|
| `username` | 是 | `^[a-z_][a-z0-9_-]{0,31}$` |
| `ssh-privatekey` | 是 | `ssh.ParsePrivateKey`；有口令的私钥（`*ssh.PassphraseMissingError`）拒绝并说明“不支持带口令的私钥”；RSA 少于 2048 位拒绝；支持 ed25519、ecdsa、rsa |
| `known_hosts` | 是 | 见下 |
| `port` | 否 | 十进制 1–65535，默认 22 |

`known_hosts`：
- 用 `ssh.ParseKnownHosts` 逐条解析：至少一条有效记录，否则报错；出现 `@cert-authority` / `@revoked` 标记直接报错“不支持”。
  同时收集出现过的密钥类型，生成 `hostKeyAlgorithms`（固定优先顺序：`ssh-ed25519`，`ecdsa-sha2-nistp256/384/521`，
  RSA 密钥对应 `rsa-sha2-512`、`rsa-sha2-256`，不用 SHA-1 的 `ssh-rsa`）。不限制算法的话，Go 客户端可能协商出 known_hosts
  里没有的密钥类型（例如只记录了 ed25519，却协商成 ecdsa），然后误报主机密钥不匹配。
- `x/crypto/ssh/knownhosts` 只能从文件构造回调：把数据写入 `os.CreateTemp("", "glusterfs-csi-known-hosts-*")`（0600），
  调 `knownhosts.New`，之后**无论成败都删除**临时文件（`defer`）。known_hosts 只含公钥，落盘不是泄密，但不能留下文件。

错误：所有错误都包装 `ErrInvalidCredentials`（新哨兵），消息只说哪个键、什么问题；**不得包含任何键的值**
（`known_hosts` 解析错误只给行号），也不得包装底层错误原文（`ssh.ParsePrivateKey` 的错误可能带有输入片段）。

私钥（signer）、回调与算法列表都是未导出字段，没有导出的取值方法。`Credentials` 实现 `String()` 与 `GoString()`，
都只返回 `username=<user> port=<port>` 这样的摘要，防止 `%v`、`%+v`、`%#v` 把私钥打印出来。

主机密钥只按主机名校验：`knownhosts` 对 `NewClientConn` 传入的地址（`host:port`）查找记录，不看对端 IP（D-12 用主机名寻址）。
端口不是 22 时 known_hosts 的记录形如 `[host]:port`（`ssh-keyscan -p` 的输出即是）。

### `ssh.go`
```go
type SSHOptions struct {
    DialTimeout time.Duration                                         // 默认 10s：连接 + 握手 + 认证的总时限
    MaxOutput   int                                                   // 默认 16 MiB：stdout 上限
    Dial        func(ctx context.Context, network, addr string) (net.Conn, error) // 默认 (&net.Dialer{}).DialContext；测试用来映射主机名
}

type SSHExecutor struct { /* creds, opts */ }

func NewSSHExecutor(creds *Credentials, opts SSHOptions) (*SSHExecutor, error) // creds 为 nil 时报错
func (e *SSHExecutor) Run(ctx context.Context, host string, args ...string) ([]byte, error)
```
`Run` 流程：
1. `validateCommand`；
2. 在 `min(ctx, DialTimeout)` 内 `Dial("tcp", net.JoinHostPort(host, port))`；对连接设 deadline = 同一时限，
   `ssh.NewClientConn(conn, addr, cfg)`（`cfg.User`、`Auth: ssh.PublicKeys(signer)`、`HostKeyCallback`、`HostKeyAlgorithms`、
   `Timeout` 不用——时限由 deadline 控制），成功后清除 deadline；握手期间 ctx 被取消要立即中断（用 `context.AfterFunc(ctx, 关闭连接)`，
   握手结束后调用它返回的 stop）；这一段的任何失败都包装 `ErrConnect`，
   并区分消息：主机不在 known_hosts（`*knownhosts.KeyError` 且 `Want` 为空）、主机密钥不匹配（`Want` 非空，消息注明“可能存在中间人”）、认证失败；
3. `NewSession`；stdout 写入上限为 `MaxOutput` 的缓冲（超限时写入返回错误）、stderr 写入只保留前 64 KiB 的缓冲（超出部分丢弃但不报错）；
   stdin 为空；
4. `session.Start(shellQuote(args))`，失败包装 `ErrConnect`（exec 请求被拒，远端未执行）；
5. 一个 goroutine 执行 `session.Wait()` 把结果送进带缓冲的 channel；`select` 等它或 `ctx.Done()`。ctx 先结束时关闭 SSH 连接
   （sshd 会给远端命令发 SIGHUP），**再等这个 goroutine 返回**后才返回——不留 goroutine；
6. `Wait` 结果：`nil` → 返回 stdout；`*ssh.ExitError` → `*ExitError`；`*ssh.ExitMissingError` → 普通错误“连接在命令结束前断开”；
   stdout 超限 → 普通错误“输出超过 N 字节”；
7. 任何路径都关闭连接（`defer`）。

`SSHExecutor` 无可变共享状态，可并发调用。

日志（klog）：`V(4)` 记录 host、argv、耗时、退出码；argv 只含经过校验的名字，可以记录。凭据、Secret 数据永不记录。

### `failover.go`
```go
// Failover runs a command on the first reachable server of a cluster.
type Failover struct {
    Executor Executor
    mu   sync.Mutex
    last map[string]string // strings.Join(hosts, ",") -> 上次成功的主机
}

func (f *Failover) Run(ctx context.Context, hosts []string, args ...string) (stdout []byte, host string, err error)
```
- 尝试顺序：上次对同一 `hosts` 列表成功过的主机（仍在列表中时）排第一，其余按 `hosts` 原顺序。这样第一台宕机时，
  不必每次都先等它的 DialTimeout。
- 某台返回的错误满足 `errors.Is(err, ErrConnect)` → 用 `V(2)` 记一行（host 与错误），尝试下一台；
  返回 `nil` 或 `*ExitError`（命令在该主机执行过，说明主机可达）→ 记为“上次成功的主机”，立即返回；其它错误（包括 ctx 取消、
  `ErrInvalidCommand`、执行中断开）→ 立即返回，不再尝试。**只在远端什么都没执行时才换主机，所以同一条命令不会执行两次。**
- 全部主机都是 `ErrConnect` → 返回 `*AllHostsFailedError{Errors []error}`（每个元素是带主机名的错误），`Unwrap() []error`
  返回这些错误，因而 `errors.Is(err, ErrConnect)` 仍为真；`Error()` 列出每台主机的原因，用 `; ` 分隔。
- `hosts` 为空 → 包装 `ErrInvalidCommand`。`last` 超过 64 项时整体清空。零值的 `Failover`（只设了 `Executor`）可直接使用。
- T-16 若要把“glusterd 未运行”（gluster 已执行但连不上本机 glusterd）也视为可换主机，可以在自己的 Executor 包装里把那种
  `ExitError` 转成包装 `ErrConnect` 的错误；本任务不做。

架构师验收：
1. 逐行评审，重点：是否有任何未 quote 的字符串到达远端；`ErrConnect` 是否只包住“远端未执行”的失败；ctx 取消路径是否不留 goroutine；

2. 变异测试（至少）：quote 不转义 `'`、某个参数不加引号、`ErrConnect` 包住 `ExitError`、`session.Start` 失败不包 `ErrConnect`、
   failover 对 `ExitError` 也换主机、忘记记录上次成功的主机、`HostKeyAlgorithms` 不设置、ctx 取消后不等 goroutine、
   允许程序列表放行 `sh`、控制字符检查漏掉 `\n`、临时文件不删除、错误消息带上底层解析错误原文。
3. 真实集群：用 `integration` 标签对 3 台 Gluster 节点（root + 架构师的 ed25519 密钥，known_hosts 由 `ssh-keyscan` 生成）跑一次。
4. CI：现有 job 全绿（integration 测试不进 CI）。

## 不要做的事
- 不要提供跳过主机密钥校验、TOFU、密码认证、带口令私钥、ssh-agent 的任何路径。
- 不要加连接池、keepalive、重试循环（同一主机不重试；换主机只在 `ErrConnect` 时）。
- 不要在远端命令前加 `sudo`、`env`、`exec` 或任何前缀；不要用 `session.Shell()`、不要申请 pty。
- 不要把私钥写到磁盘；不要把凭据、Secret 数据放进错误消息、日志或 panic。
- 不要接入 `pkg/driver`、`cmd/`、`pkg/config`，不要定义 gluster 子命令封装或 XML 结构（T-16）。
- 不要用 `golang.org/x/crypto` 以外的 SSH 库，不要调用本机的 `ssh` 二进制。
