# T-03 pkg/config：集群配置加载与热更新

**状态**：已验收（2026-10-31，返工 1 次）
**执行者**：pi / deepseek-flash
**允许改动的文件**：仅 `pkg/config/` 下的文件（`config.go`、`store.go`、`config_test.go`、`store_test.go`，可选 `doc.go`、`testdata/`）。
不得修改 `go.mod`/`go.sum`、`cmd/`、`docs/`、`AGENTS.md` 及其他包。本任务**不**接入 `main.go`（T-04 负责）。
**依赖**：标准库 + 已有的 `k8s.io/klog/v2` + 本仓库 `pkg/volumeid`。**禁止**引入 fsnotify、apimachinery 等新依赖；`go.mod`/`go.sum` 必须保持不变。

## 背景
集群连接信息放在 ConfigMap `glusterfs-csi-config`，以文件形式挂进容器，默认路径 `/etc/glusterfs-csi/config.json`
（`--config` 参数，见 `docs/architecture.md` §5.1、`docs/usage.md` §2）。volume_id 里只有 `clusterID`，
服务器地址变化只改 ConfigMap、不改 PV，所以驱动必须在**不重启**的情况下读到新配置。

Kubernetes 更新 ConfigMap 卷的方式是：写入新的时间戳目录，再原子替换 `..data` 符号链接；
`config.json` 本身是指向 `..data/config.json` 的符号链接。文件 inode 会变，fsnotify 监听单个文件并不可靠，
因此本任务用**轮询 + 内容比对**实现热更新，不引入新依赖。

## 文件格式
JSON 数组，每个元素一个集群：
```json
[
  {
    "clusterID": "prod",
    "servers": ["dxt-gluster-node-1", "dxt-gluster-node-2", "10.0.0.13"],
    "executorSecretRef": { "name": "glusterfs-ssh", "namespace": "glusterfs-csi" }
  }
]
```

## 公开 API（签名必须一致）
```go
package config

// MaxFileSize 与 ConfigMap 的 1 MiB 上限一致。
const MaxFileSize = 1 << 20

// MaxServers 是单个集群允许的最大服务器数量。
const MaxServers = 32

// ErrInvalid 是所有配置内容/校验错误的哨兵，errors.Is(err, ErrInvalid) 必须成立。
// 文件读取失败（不存在、无权限）不 wrap ErrInvalid，保留原始 *fs.PathError。
var ErrInvalid = errors.New("invalid glusterfs-csi config")

type SecretRef struct {
	Name      string `json:"name"`
	Namespace string `json:"namespace"`
}

type Cluster struct {
	ClusterID         string     `json:"clusterID"`
	Servers           []string   `json:"servers"`
	ExecutorSecretRef *SecretRef `json:"executorSecretRef,omitempty"`
}

// Config 是一份不可变快照，并发读安全。
type Config struct { /* 私有字段：map[string]Cluster */ }

func Parse(data []byte) (*Config, error)
func Load(path string) (*Config, error)              // 读文件（上限 MaxFileSize）+ Parse

// Get 返回深拷贝（Servers 切片、ExecutorSecretRef 指针都要复制），调用方修改返回值不影响快照。
func (c *Config) Get(clusterID string) (Cluster, bool)
// ClusterIDs 返回升序排列的全部 clusterID。
func (c *Config) ClusterIDs() []string

// Store 持有当前配置，后台轮询文件并原子替换。
type Store struct { /* path、atomic.Pointer[Config]、上次读取内容的哈希、上次失败内容的哈希 */ }

// NewStore 同步加载一次；文件不存在或内容非法时返回错误（驱动启动即失败，快速暴露配置问题）。
func NewStore(path string) (*Store, error)
// Current 返回当前快照，永不返回 nil。
func (s *Store) Current() *Config
// Run 每隔 interval 检查一次文件，直到 ctx 结束才返回；interval <= 0 时使用 10s。
// 调用方负责在 goroutine 中运行它，ctx 取消即退出（满足“goroutine 必须有停止路径”）。
func (s *Store) Run(ctx context.Context, interval time.Duration)
```
内部建议拆出 `func (s *Store) reload() (changed bool, err error)`，`Run` 每个 tick 调用它；测试直接调用 `reload` 保证确定性，
不要在测试里用 `time.Sleep` 等轮询结果（`Run` 的测试除外，见下）。

## 校验规则（Parse）
1. 解码使用 `json.Decoder` + `DisallowUnknownFields()`；顶层必须是数组；数组之后不得有多余内容（再 `Decode` 一次必须得到 `io.EOF`）。
2. 至少 1 个集群；`clusterID` 不得重复。
3. `clusterID`：调用 `volumeid.ValidateName("clusterID", v)`。
4. `servers`：1 ~ `MaxServers` 个；每个必须是以下之一：
   - IP 地址：`netip.ParseAddr` 成功，且**不带 zone**（拒绝 `fe80::1%eth0`）；
   - 主机名：RFC 1123，总长 ≤ 253，每个 label 1~63 个 `[A-Za-z0-9-]`，label 不以 `-` 开头或结尾，不允许末尾的 `.`。
   - 不允许带端口（`host:24007`）、空串、空白、协议前缀等。
   - 同一集群内重复（大小写不敏感）→ 非法。
   - 保持原始顺序（顺序即故障转移顺序与 `backup-volfile-servers` 顺序）。
5. `executorSecretRef` 可省略；出现时 `name` 必须是 DNS-1123 subdomain（≤253，`[a-z0-9]([-a-z0-9]*[a-z0-9])?` 用 `.` 连接），
   `namespace` 必须是 DNS-1123 label（≤63，`[a-z0-9]([-a-z0-9]*[a-z0-9])?`），两者都必填。
6. 错误信息要定位到元素，例如 `invalid glusterfs-csi config: clusters[1] (clusterID "prod"): servers[2] "a b": not a valid hostname or IP address`，
   并 wrap `ErrInvalid`。错误信息里不得包含整份文件内容。
7. 正则全部包级预编译。

## 热更新规则（Store）
- `Load` 用 `io.LimitReader(f, MaxFileSize+1)` 读取，超过 `MaxFileSize` → `ErrInvalid`。路径经 `os.Open` 跟随符号链接。
- 每次 `reload`：读文件 → 计算 sha256 → 与上次**成功读取**的内容哈希相同则 `changed=false, err=nil`（不解析、不打日志）。
- 内容变化且 `Parse` 成功 → 原子替换快照，`klog.InfoS("glusterfs-csi config reloaded", "path", p, "clusters", ids)`，返回 `changed=true`。
- 内容变化但非法 → **保留旧快照**，返回错误；`Run` 用 `klog.ErrorS` 记录。同一份非法内容只记录一次（记住失败内容的哈希），
  文件被改回合法或改成另一份非法内容时才再次处理。
- 文件暂时读不到（ConfigMap 原子切换瞬间、被删除）→ 保留旧快照，返回错误，`Run` 记录日志；之后文件恢复照常加载。
- 日志里只出现 path、clusterID 列表和错误原因，不打印整份文件内容；配置里只有 Secret 的引用，没有 Secret 内容。
- `Run` 内用 `time.NewTicker` 并 `defer ticker.Stop()`；不得启动额外 goroutine。

## 测试（表驱动，断言行为）
`config_test.go`
1. `TestParse` 合法用例：单集群、多集群、IPv4/IPv6/主机名混用、省略 executorSecretRef；断言 `Get` 结果与 `ClusterIDs` 排序。
2. `TestParse` 非法用例（全部断言 `errors.Is(err, ErrInvalid)`，部分断言错误信息包含定位片段）：
   空输入、`{}`（不是数组）、`[]`、未知字段 `"server"`、数组后多余内容 `[...] []`、clusterID 为空 / `..` / `-x` / `a;b`、
   clusterID 重复、servers 缺失 / 空数组 / 33 个、server 为 `""`、`"a b"`、`"host:24007"`、`"-host"`、`"host-"`、`"a..b"`、
   `"host."`、64 字符的 label、254 字符的主机名、`"fe80::1%eth0"`、`"http://host"`、大小写不同的重复 server、
   executorSecretRef 缺 name / 缺 namespace / name 含大写 / namespace 含 `.`。
3. `TestGetReturnsCopy`：修改 `Get` 返回的 `Servers[0]` 和 `ExecutorSecretRef.Name`，再次 `Get` 值不变。
4. `TestLoad`：文件不存在返回的错误满足 `errors.Is(err, fs.ErrNotExist)` 且**不**满足 ErrInvalid；
   超过 `MaxFileSize` 返回 ErrInvalid；合法文件加载成功。

`store_test.go`（全部使用 `t.TempDir()`）
5. `TestNewStore`：合法 → 成功且 `Current()` 非 nil；不存在 / 非法 → 返回错误。
6. `TestStoreReload`（顺序步骤的表或子测试）：
   未变化 → `changed=false`；改成新的合法内容 → `changed=true` 且 `Current()` 反映新 servers；
   改成非法 → 返回 ErrInvalid 且 `Current()` 仍是旧值；同一非法内容再 reload → 仍保留旧值；改回合法 → 生效；
   删除文件 → 返回错误、保留旧值；重新写回 → 生效。
7. `TestStoreReloadKubernetesSymlinkSwap`：按 kubelet 的布局构造 `..2026_01_01/config.json`、`..data -> ..2026_01_01`、
   `config.json -> ..data/config.json`，然后建新时间戳目录并用 `os.Rename` 原子替换 `..data` 符号链接，断言 reload 读到新内容。
8. `TestStoreRunStopsOnCancel`：goroutine 中 `Run(ctx, 5*time.Millisecond)`，写入新合法内容后在 2s 截止时间内轮询 `Current()` 直到生效，
   然后 `cancel()`，断言 `Run` 在 2s 内返回（用 done channel）。
9. `TestStoreConcurrentAccess`：多个 goroutine 循环调用 `Current().Get(...)`，同时主 goroutine 反复改文件并 reload；在 `-race` 下无数据竞争。
