## 背景（必读）
node 插件容器退出时，容器内的 glusterfs FUSE 进程随之退出，宿主机上的 staging 挂载和各 Pod 的 bind 挂载都变成 `ENOTCONN`。
kubelet 不会为已 staged 的卷再次调用 NodeStage，所以插件必须自己修复。决策（docs/decisions.md）：
- **D-19**：恢复器在宿主机上重挂 staging，并刷新各 Pod 的 bind 挂载；业务容器能否看到恢复取决于它的 `mountPropagation`，这不是本任务的代码问题。
  恢复器**不删除**任何 Pod。
- **D-20**：启动时扫描一次，之后每 `--recovery-interval`（默认 60s；0 表示只在启动时）扫描一次。NodeStage 成功后在 `--state-dir`
  写一份 staging 记录，NodeUnstage 成功后删除；`--state-dir` 为空时既不写记录也不运行恢复器。

**关键事实**：mount-utils 的 `GetMountRefs`（以及基于它的 `OtherBindMounts`）遇到损坏的挂载点**直接返回空列表**，所以找 bind target
必须自己解析 mountinfo：与 staging 条目 `Major`、`Minor`、`Root` 都相同的其它条目就是它的 bind 挂载。**必须在卸载 staging 之前**找，
卸载之后 staging 条目就从 mountinfo 消失了。

## 设计

### `pkg/mounter`
```go
// BindTarget is a mount point that shows the file system of another mount point.
type BindTarget struct {
	// Path is the mount point, absolute and clean.
	Path string
	// ReadOnly is true when the per-mount options contain "ro".
	ReadOnly bool
}
```
`Mounter` 接口新增：
```go
// BindTargets returns the other mount points of the file system mounted at
// source, read from mountinfo: same major:minor and same root. Unlike
// OtherBindMounts it works when source is a corrupted mount point, which is
// when the recovery needs it. A source that is not a mount point returns an
// empty list.
BindTargets(source string) ([]BindTarget, error)
// Detach lazily unmounts target (MNT_DETACH), which succeeds even while
// processes still use the dead mount. A target that does not exist or is not
// a mount point is success.
Detach(target string) error
```
`mounter` 结构体新增字段 `mountInfoPath string`（`New` 设为 `"/proc/self/mountinfo"`）与 `detach func(target string) error`
（`New` 设为平台实现 `detachMount`）。两个字段让包内测试可以注入 fixture 文件和假的 detach；不提供导出的设置方式。

`BindTargets(source)`：
1. `validatePath("source", source)`，失败返回 `ErrInvalidSpec`。
2. `infos, err := parseMountInfo(m.mountInfoPath)`；失败返回 `fmt.Errorf("read mountinfo %q: %w", ...)`。
3. 返回 `bindTargetsFrom(infos, source, resolved)`。`resolved` 为 `filepath.Join(EvalSymlinks(filepath.Dir(source)), filepath.Base(source))`；
   父目录解析失败时等于 `source`。**不得**对 `source` 本身调用 `EvalSymlinks` 或 stat：它可能是损坏的挂载点。

`bindTargetsFrom(infos []mount.MountInfo, source, resolved string) []BindTarget`（纯函数，所有平台都能测）：
- 在 `infos` 中找 `MountPoint == source || MountPoint == resolved` 的**最后一个**条目（叠加挂载时最上层在后）；找不到返回空切片（非 nil）。
- 收集其它满足 `Major`、`Minor`、`Root` 都相等、且 `MountPoint` 不等于 `source`/`resolved` 的条目；`MountPoint` 不是绝对干净路径的条目跳过。
- 按 `MountPoint` 去重（后出现的覆盖先出现的 `ReadOnly`），保持首次出现的顺序。`ReadOnly = slices.Contains(info.MountOptions, "ro")`。

平台文件：
- `mountinfo_unix.go`（`//go:build !windows`）：`func parseMountInfo(path string) ([]mount.MountInfo, error) { return mount.ParseMountInfo(path) }`
- `mountinfo_windows.go`：返回 `nil, errors.ErrUnsupported`（包装路径）。
- `detach_linux.go`：`syscall.Unmount(target, syscall.MNT_DETACH)`；`ENOENT`、`EINVAL`（不是挂载点）→ nil；其它错误 `fmt.Errorf("detach %q: %w", target, err)`。
- `detach_other.go`（`//go:build !linux`）：返回包装了 `errors.ErrUnsupported` 的错误。

`Detach(target)`：`validatePath("target", target)` 后调用 `m.detach(target)`，成功时 `klog.V(2)` 记录。

### `pkg/driver/stagerecord.go`
```go
const stageRecordVersion = 1

// stageRecord is what NodeStageVolume leaves behind for the recovery. It holds
// no secret and no server: the servers are looked up in the live
// configuration at recovery time, so that a changed server list is used.
type stageRecord struct {
	Version           int            `json:"version"`
	VolumeID          string         `json:"volumeID"`
	StagingTargetPath string         `json:"stagingTargetPath"`
	ReadOnly          bool           `json:"readOnly"`
	MountFlags        []string       `json:"mountFlags,omitempty"`
	// Targets are the bind targets of an interrupted recovery: found before
	// the staging mount was detached and not yet bound again.
	Targets           []recordTarget `json:"targets,omitempty"`
}

type recordTarget struct {
	Path     string `json:"path"`
	ReadOnly bool   `json:"readOnly"`
}

// recordStore keeps one file per staged volume in dir.
type recordStore struct{ dir string }
```
- 文件名 `recordFileName(volumeID) = hex(sha256(volumeID)) + ".json"`（volume_id 不直接进路径）。
- `save(rec)`：`os.MkdirAll(dir, 0o700)`；`os.CreateTemp(dir, ".tmp-*")` 写 JSON、`Sync`、`Close`、`Chmod 0o600`、`os.Rename` 到目标文件名；
  任一步失败删除临时文件并返回错误。写入前先 `rec.validate()`。
- `loadFile(name)`：用 `io.LimitReader` 读最多 64 KiB；JSON 解析；`validate()`；校验 `recordFileName(rec.VolumeID) == name`。
  文件不存在时返回的错误满足 `errors.Is(err, fs.ErrNotExist)`；其余失败包装哨兵 `errInvalidRecord`。
- `load(volumeID)` = `loadFile(recordFileName(volumeID))`。
- `remove(volumeID)`：不存在视为成功。
- `list()`：目录不存在返回 `nil, nil`；返回以 `.json` 结尾、不以 `.` 开头的普通文件名，按名字排序。
- `validate()`：`Version == stageRecordVersion`；`volumeid` 能解码 `VolumeID`；`StagingTargetPath` 与每个 `Targets[i].Path`
  通过 `validatePath`（绝对且干净）。`MountFlags` 不在这里校验，重挂时由 `BuildMountArgs` 的白名单校验。

### `pkg/driver/node.go`
- `nodeService` 新增 `records *recordStore`（`--state-dir` 为空时为 nil）。
- NodeStageVolume：`mountGlusterfs` 成功后，若 `s.records != nil`，`save(stageRecord{Version, VolumeID, StagingTargetPath, ReadOnly: capability.readOnly, MountFlags: capability.mountFlags})`
  （`Targets` 为空：一次成功的 Stage 清除未完成的恢复）。失败返回 `Internal`（`"record staged volume %s: %v"`），挂载保留，重试是幂等的。
- NodeUnstageVolume：`Unmount` 成功后 `remove`；失败返回 `Internal`。卸载失败时**不删**记录。

### `pkg/driver/recovery.go`
```go
type recoveryOutcome int

const (
	recoveryHealthy   recoveryOutcome = iota // nothing to do
	recoveryBusy                             // the stage lock is held; retried by the next pass
	recoveryStale                            // the record was removed
	recoveryMismatch                         // something else is mounted at the staging path; left alone
	recoveryRecovered                        // remounted and/or refreshed, nothing pending
	recoveryPartial                          // some targets are still pending
)

// runRecovery runs one pass at once and then one per interval until ctx is
// done. interval <= 0 runs the first pass only.
func (s *nodeService) runRecovery(ctx context.Context, interval time.Duration)

// recoverAll runs one pass over all records and returns how many records ended
// in each outcome, plus the number of failures.
func (s *nodeService) recoverAll(ctx context.Context) recoverySummary

func (s *nodeService) recoverVolume(ctx context.Context, name string) (recoveryOutcome, error)
```
`recoverVolume(name)`，严格按以下顺序：
1. `loadFile(name)` 失败 → 返回错误（无效记录保留，交给运维排查）。
2. `tryAcquire(nodeStageLockPrefix + rec.VolumeID)`；被占用 → `recoveryBusy, nil`。持锁后 `load(rec.VolumeID)` **重新读取**：
   `fs.ErrNotExist`（期间被 Unstage）→ `recoveryHealthy, nil`；其它错误 → 返回错误。
3. `state, err := s.mounter.VolumeMountState(rec.StagingTargetPath, id.Volume, id.Subdir)`；err → 返回错误。
4. 按 state 分支：
   - `Mismatch` → 记 warning，`recoveryMismatch, nil`。
   - `Mounted` → `Targets` 为空则 `recoveryHealthy, nil`；否则跳到第 6 步。
   - `NotMounted` → 若 `Targets` 中**没有**处于 `Corrupted` 状态的 target（例如节点重启后挂载全没了，kubelet 会自己重新 Stage）→
     删除记录，`recoveryStale, nil`；否则跳到第 5 步。
   - `Corrupted` → (a) `found, err := BindTargets(staging)`，失败返回错误且什么都不改；(b) `rec.Targets = merge(rec.Targets, found)`
     （按 Path 去重，`found` 的 ReadOnly 优先）；(c) `save(rec)`，失败返回错误且不 detach；(d) `Detach(staging)`，失败返回错误；然后第 5 步。
5. 重挂：`s.cluster(id.ClusterID)` 不存在 → 返回错误（记录保留）；`ensureLogDir`；
   `MountGlusterfs(ctx, Spec{Servers: 当前配置的 servers, Volume, Subdir, ReadOnly: rec.ReadOnly, Options: rec.MountFlags}, staging)`；
   失败 → 返回错误（记录里的 `Targets` 保留，下一轮重试）。
6. 刷新 target：对 `rec.Targets` 逐个：`tryAcquire(nodePublishLockPrefix + t.Path)`，被占用 → 留在待刷新列表；
   `VolumeMountState(t.Path, ...)`：出错 → 留下；`Corrupted` → `Detach(t.Path)` 然后 `BindMount(ctx, staging, t.Path, t.ReadOnly)`，任一失败 → 留下；
   `Mounted`/`NotMounted`/`Mismatch` → 从列表移除（已经好了、已被 Unpublish、或不归我们管）。释放锁。
   列表有变化时 `save(rec)`（失败返回错误）。
7. 结果：列表非空 → `recoveryPartial, nil`；重挂或至少一个 target 刷新成功 → `recoveryRecovered, nil`；否则 `recoveryHealthy, nil`。

`recoverAll`：`list()` 失败记错误日志并返回；按名字顺序逐个处理，每个之前检查 `ctx.Err()`，已取消就停止；
每个记录一行日志（错误用 `klog.ErrorS`，恢复成功 `klog.InfoS`，健康 `klog.V(4)`）；pass 结束 `klog.InfoS` 汇总（仅当有非 healthy 结果时）。

### `pkg/driver/driver.go`
- `Options` 新增 `StateDir string`、`RecoveryInterval time.Duration`。
- `New`：`StateDir` 非空时必须是绝对且干净的路径；`RecoveryInterval < 0` → 错误。node 模式下 `StateDir != ""` 时 `records = &recordStore{dir}`。
- `Serve`：gRPC server 开始服务后，若 `d.node != nil && d.node.records != nil`，用从 `ctx` 派生的 context 启动 `runRecovery` goroutine；
  `Serve` 在**任何**返回路径上都先取消该 context 再等待 goroutine 退出（`sync.WaitGroup`）。恢复在后台运行，不阻塞 kubelet 的调用。

### `cmd/glusterfs-csi/main.go`
- `--state-dir`，默认常量 `DefaultStateDir = "/var/lib/kubelet/plugins/glusterfs.csi.io/staged"`；帮助文本说明空值关闭记录与恢复。
- `--recovery-interval`（`time.Duration`），默认 `60s`；0 表示只在启动时扫描；`validateFlags` 拒绝负值。
- 两个值传给 `driver.Options`。

## 测试（表驱动，断言行为）
1. `TestBindTargetsFrom`（纯函数）：正常（staging + 两个 bind，一个 `ro`）→ 两个 target 且 ReadOnly 正确；Root 不同的条目排除；Minor 不同的排除；
   staging 不在表中 → 空切片；staging 叠加挂载两次 → 用最后一个条目的设备号；通过 `resolved` 匹配；相同 MountPoint 出现两次 → 去重；
   相对路径的 MountPoint 被跳过。
2. `TestBindTargets`：把 fixture 写进 `t.TempDir()` 下的 mountinfo 文件（真实的 mountinfo 行格式，含 `fuse.glusterfs` 与 `- ` 分隔符），
   设置 `mountInfoPath`；文件不存在 → 错误；相对 source → `ErrInvalidSpec`。
3. `TestDetach`：注入 `detach` 记录调用；非法路径 → `ErrInvalidSpec` 且未调用；注入的错误原样包装返回。
4. `detach_linux_test.go`（`//go:build linux`）：非 root 时 `t.Skip`；root 时对一个未挂载的临时目录和不存在的路径返回 nil。
5. `TestRecordStore`：save → load 往返相等；文件权限 0600；目录不存在时 list 为空；list 忽略 `.tmp-*` 与非 `.json`；remove 两次都成功；
   改名后的文件（名字与 sha256 不符）→ `errInvalidRecord`；版本号 2 → `errInvalidRecord`；坏 JSON → `errInvalidRecord`；
   staging 为相对路径或 target 含 `..` → save 与 load 都拒绝；超过 64 KiB 的文件被拒绝。
6. NodeStage/NodeUnstage（`node_test.go`）：设置了 records 时 Stage 成功后记录存在且字段正确（含 mount flags 与只读）；挂载失败时不写记录；
   state dir 不可写（指向一个普通文件）→ `Internal`；records 为 nil 时不写；Unstage 成功删除记录；Unmount 失败时记录仍在；重复 Unstage 成功。
7. `TestRecoverVolume`（fakeMounter 记录**有序的调用日志**，如 `"bindTargets:/s"`、`"detach:/s"`、`"mount:/s"`、`"bind:/s->/t1:ro"`；
   fake 的 Detach 把该路径状态设为 NotMounted，成功的 MountGlusterfs/BindMount 设为 Mounted）：
   - Mounted、无 Targets → healthy，没有任何挂载调用；
   - Mismatch → mismatch，没有调用；
   - Corrupted，两个 bind（一个 ro）→ 调用顺序**严格**为 bindTargets → (记录已保存 Targets) → detach staging → mount → 对每个 target detach → bind；
     mount 的 Spec 用**当前配置**的 servers、记录的 flags 与 ReadOnly；结束后记录的 Targets 为空，outcome recovered；
   - Corrupted 但 mount 失败 → 返回错误；记录里仍有两个 Targets；target 没有被 detach；
   - 上一种之后再跑一次（staging 现在 NotMounted，target 仍 Corrupted）→ 重挂并刷新，Targets 清空；
   - NotMounted 且无 Corrupted target → 记录被删除，stale，没有 mount；
   - 记录的 cluster 不在配置中 → 错误，记录保留；
   - stage 锁被持有 → busy，没有任何 mounter 调用；
   - 某个 target 的 publish 锁被持有 → partial，该 target 留在记录中，另一个已刷新；
   - 某个 target BindMount 失败 → partial，留在记录中；
   - Mounted 但记录里有 Targets（其中一个 Corrupted、一个 Mounted）→ 只刷新 Corrupted 的那个，Targets 清空；
   - BindTargets 失败 → 错误，没有 detach；
   - 无效记录文件 → 错误，文件仍在；
   - 加载后、持锁前记录被删 → healthy。
8. `TestRunRecovery`：interval 0 → 恰好一轮后返回；interval 10ms → 至少两轮，取消 ctx 后在 1s 内返回；ctx 已取消时 recoverAll 不处理任何记录。
9. `driver_test.go`：`StateDir` 相对或不干净 → New 报错；`RecoveryInterval` 为负 → 报错；StateDir 为空时不启动恢复；
   Serve 在 ctx 取消后返回且恢复 goroutine 已退出（例如 `goleak` 不可用时用计数或 channel 断言，不要引入新依赖）。
10. `main_test.go`：两个 flag 的默认值、解析、负的 interval 被拒绝。

## 验收标准
- `go build ./... && go vet ./... && golangci-lint run && go test -race ./...` 全绿；`GOOS=linux go vet ./...` 与 `GOOS=windows go build ./...` 也通过；
  `go mod tidy` 后 go.mod/go.sum 无变化。

- 架构师会在 Linux 容器内以 root 运行 `go test ./pkg/mounter/`（覆盖 `detach_linux.go`）。
- 架构师会做变异测试，以下改动测试必须失败：先 detach 再 BindTargets；detach 前不保存 Targets；NotMounted 一律删除记录；
  NotMounted 一律重挂；刷新 target 时不 detach；忽略 target 的 ReadOnly；Stage 不写记录；Unstage 不删记录；loadFile 不校验文件名；
  bindTargetsFrom 不比较 Root；不比较 Minor；重挂 Spec 的 servers 不取当前配置；忽略 stage 锁。

  记录文件不含 Secret 与 servers。
- 真实集群验收（插件 Pod 被删后一个周期内 staging 与 bind 恢复，HostToContainer 的业务 Pod I/O 恢复）在 T-09 部署清单完成后执行。
