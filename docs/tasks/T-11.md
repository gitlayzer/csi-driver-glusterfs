### 2. `pkg/driver/parentmount.go`：父卷挂载缓存（D-24）
```go
// parentMounts keeps one glusterfs mount per parent volume for the controller
// service (D-24) and hands out an *os.Root opened on each mount.
type parentMounts struct {
	mounter mounter.Mounter
	dir     string        // Options.ControllerMountDir
	sem     chan struct{} // capacity 1; a lock a cancelled ctx can stop waiting for
	roots   map[string]*os.Root  // key: mount path
	mounted map[string]struct{}  // mount paths this process mounted, for close
}

func newParentMounts(m mounter.Mounter, dir string) *parentMounts
func (p *parentMounts) root(ctx context.Context, cluster config.Cluster, volume string) (*os.Root, error)
func (p *parentMounts) close(ctx context.Context)
```
`root`：
1. 再次 `volumeid.ValidateName` 校验 `cluster.ClusterID` 与 `volume`（防御，路径由它们拼出）。
2. 用 `select` 获取 `sem`；`ctx` 先结束则返回 `ctx.Err()`（不得无限等待）。返回前释放。
3. 挂载点 `path = filepath.Join(p.dir, cluster.ClusterID, volume)`。`state, err := p.mounter.VolumeMountState(path, volume, "")`：
   - `Mounted`：有缓存的 root 就返回它；没有就 `os.OpenRoot(path)`、缓存、返回。
   - `NotMounted`：关闭并丢弃该路径缓存的 root（它可能指向挂载点下的本地目录）；`os.MkdirAll(path, 0o750)`；
     `MountGlusterfs(ctx, mounter.Spec{Servers: cluster.Servers, Volume: volume}, path)`；成功后记入 `mounted`，再 `OpenRoot`、缓存、返回。
   - `Corrupted`：关闭并丢弃缓存的 root；`Detach(path)`；然后按 `NotMounted` 处理。
   - `Mismatch`：返回错误（"something else is mounted at %s"），**不卸载**、不挂载。
   - `err != nil`：返回错误。
4. **只有挂载成功之后才打开 root**；任何失败路径都不得缓存 root。
5. 被替换的旧 root 关闭后，其它 goroutine 手里的旧 root 上的操作会以 `os.ErrClosed` 失败 —— 这是预期行为（失败后 CO 重试），
   绝不能让操作落到挂载点下的本地目录。在注释中说明。

`close`：获取 `sem`（同样尊重 ctx）；关闭全部 root；对 `mounted` 中每个路径调用一次 `Unmount(ctx, path)`，错误只记日志；清空两个 map。
重复调用是 no-op。

### 3. `pkg/driver/subdirvolume.go`：父卷上的目录与元数据操作（D-25/26/27）
全部函数只接受 `*os.Root` 与已校验的卷名，是纯文件系统操作，用 `t.TempDir()` 上的 `os.OpenRoot` 即可单测。
```go
const (
	metaDirName       = ".glusterfs-csi"
	metaVolumesDir    = ".glusterfs-csi/volumes"   // 用 filepath.Join 拼，勿硬编码分隔符
	metaArchiveDir    = ".glusterfs-csi/archive"
	volumeDirPerm     = 0o777
	metaDirPerm       = 0o755
	metaFilePerm      = 0o644
	maxMetaFileSize   = 64 << 10
	archiveTimeLayout = "20060102T150405.000000000Z"
	metaVersion       = 1
)

// volumeMeta is the content of .glusterfs-csi/volumes/<name>.json.
type volumeMeta struct {
	Version       int          `json:"version"`
	CapacityBytes int64        `json:"capacityBytes"`
	OnDelete      deletePolicy `json:"onDelete"`
}

func readVolumeMeta(root *os.Root, name string) (meta volumeMeta, found bool, err error)
func writeVolumeMeta(root *os.Root, name string, meta volumeMeta) error
func removeVolumeMeta(root *os.Root, name string) error
func volumeDirExists(root *os.Root, name string) (bool, error)
func ensureVolumeDir(root *os.Root, name string) error
func archiveVolumeDir(root *os.Root, name string, now time.Time) error
func removeVolumeDir(ctx context.Context, root *os.Root, name string) error
```
- `readVolumeMeta`：不存在 → `found=false, err=nil`。读取最多 `maxMetaFileSize+1` 字节，超过即错误；`json.Decoder` +
  `DisallowUnknownFields`，且文件末尾不得有多余内容；`Version != metaVersion`、`OnDelete` 不是三个合法值之一、`CapacityBytes < 0` → 错误。
  错误消息不得回显文件内容。
- `writeVolumeMeta`：`MkdirAll(metaVolumesDir, metaDirPerm)`；写临时文件 `volumes/.<name>.json.tmp`（`O_WRONLY|O_CREATE|O_TRUNC`）→
  `Sync` → `Close` → `Rename` 为 `volumes/<name>.json`。任一步失败都尽力删除临时文件。
- `removeVolumeMeta`：删除；不存在视为成功。
- `volumeDirExists`：`Lstat`；不存在 → false；是目录（不是符号链接）→ true；其它（普通文件、符号链接）→ 错误。
- `ensureVolumeDir`：`Mkdir(name, volumeDirPerm)`，已存在且是真目录则继续，否则报错；**之后总是** `Chmod(name, volumeDirPerm)`（umask 会削掉权限位，
  重复调用也要修正）。
- `archiveVolumeDir`：`MkdirAll(metaArchiveDir, metaDirPerm)`；`Rename(name, archive/<name>-<now.UTC().Format(archiveTimeLayout)>)`。
- `removeVolumeDir`：`Lstat(name)` 不存在 → nil；不是真目录 → 报错（不删）。`sub, _ := root.OpenRoot(name)`；循环：打开 `"."`、
  `ReadDir(256)` 读一批、关闭目录句柄；每个条目前检查 `ctx.Err()`，然后 `sub.RemoveAll(entry)`；读不到条目为止。最后关闭 `sub` 并
  `root.Remove(name)`。`ctx` 结束时返回 `ctx.Err()` 并保留剩余内容（下次 DeleteVolume 继续）。取消粒度是卷目录下的一个顶层条目，在注释中说明。
  `os.Root.RemoveAll` 不跟随符号链接，也不会越出 `sub`。

### 4. `controller.go`：RPC
`controllerService` 新增 `parents *parentMounts` 与 `now func() time.Time`（生产为 `time.Now`，测试可替换）。

错误映射辅助：`backendError(ctx, op string, err error) error` —— `ctx.Err() != nil` 时返回 `ctxStatus(ctx)`，否则
`status.Errorf(codes.Internal, "%s: %v", op, err)`。所有父卷/文件系统失败都走它。

**ControllerGetCapabilities**：`CREATE_DELETE_VOLUME`、`SINGLE_NODE_MULTI_WRITER`，按此顺序。删除 T-10 注释中"T-11 才声明"的过时内容。

**CreateVolume**，按顺序：
1. `name` 为空 → `InvalidArgument`；`volumeid.ValidateName("name", name)` 失败 → `InvalidArgument`；以 `.` 开头 → `InvalidArgument`
   （为 `.glusterfs-csi` 保留）。
2. `volume_capabilities` 为空 → `InvalidArgument`；逐个 `checkControllerCapability`：`err` 原样返回；不支持 → `InvalidArgument`（带 reason）。
3. 容量：`required_bytes < 0` 或 `limit_bytes < 0` → `InvalidArgument`；`limit > 0 && required > limit` → `InvalidArgument`。
   记录的容量 `capacity = required`，`required == 0` 时取 `limit`（都为 0 则为 0，表示未知）。subdir 在 M2 不强制容量。
4. `volume_content_source != nil` → `InvalidArgument`（不支持快照/克隆）；`mutable_parameters` 非空 → `InvalidArgument`。
   `accessibility_requirements` 忽略（不声明拓扑）。`secrets` 不使用、不记录。
5. `parseVolumeParameters(parameters)` 失败 → `InvalidArgument`（消息即错误文本）。cluster 不在配置 → `InvalidArgument`
   （"cluster %q is not configured"）。
6. `id := volumeid.ID{Mode: subdir, ClusterID, Volume: ParentVolume, Subdir: name}`，`volumeid.Encode` 失败（如超长）→ `InvalidArgument`。
7. mount flags：复用 T-10 的 `checkMountFlags`，有 reason → `InvalidArgument`（第一条）。
8. `ctxStatus(ctx)`；以编码后的 volume id 为键 `locks.tryAcquire`，失败 → `Aborted`，`defer release`。
9. `root, err := parents.root(...)` → `backendError`。
10. `readVolumeMeta`（错误 → `backendError`）：
    - **找到**：兼容条件 `meta.OnDelete == params.OnDelete && (required == 0 || meta.CapacityBytes >= required) && (limit == 0 || meta.CapacityBytes <= limit)`；
      不兼容 → `AlreadyExists`（说明哪一项不符）。兼容 → `ensureVolumeDir`（补上"元数据写了但目录没建"的崩溃中间态）→ 返回，容量用 `meta.CapacityBytes`。
    - **没找到**：`volumeDirExists` 为 true → `AlreadyExists`（"directory %q exists in parent volume %q but was not created by this driver"），
      **不改动该目录**；否则 `writeVolumeMeta{metaVersion, capacity, params.OnDelete}` → `ensureVolumeDir` → 返回。
11. 响应：`Volume{VolumeId: 编码后的 id, CapacityBytes: 上面的容量, VolumeContext: {clusterID, volume: 父卷, subdir: name}}`，
    其它字段为空。新建时 `klog.InfoS("created volume", ...)`；幂等重复只记 `V(4)`。

**DeleteVolume**，按顺序：
1. `volume_id` 为空 → `InvalidArgument`。
2. 无法解码 → **OK**（不存在的卷，CSI 规范要求成功），`V(4)` 日志。
3. `id.Mode != subdir` → **OK**，不挂载、不触碰任何东西（static 卷不是本驱动创建的；volume 模式 M2 不存在），`V(2)` 日志说明原因。
4. cluster 不在配置 → `FailedPrecondition`（返回 OK 会让 PV 被删而数据悄悄留下；报错让管理员看到并恢复配置）。
5. `ctxStatus`；以 volume id 加锁，失败 → `Aborted`。
6. `parents.root` → `backendError`。
7. `readVolumeMeta`、`volumeDirExists`，任一出错 → `backendError`，**此时不得删除任何东西**。
8. 没有元数据：目录存在 → `klog.InfoS`（级别 0）说明"目录不是本驱动创建的，保留"，返回 OK；目录不存在 → OK。
9. 有元数据，按 `meta.OnDelete`：
   - `delete`：`removeVolumeDir(ctx, ...)`，出错 → `backendError`（元数据保留，重试继续）。
   - `retain`：不动目录。
   - `archive`：目录存在时 `archiveVolumeDir(root, name, s.now())`，出错 → `backendError`。
   然后 `removeVolumeMeta`，出错 → `backendError`。`klog.InfoS("deleted volume", "volumeID", ..., "onDelete", ...)`。返回 OK。

**ValidateVolumeCapabilities**（D-23 后半）：在 T-10 第 4 步（cluster 检查）之后、收集不支持原因之前，对 subdir id：
`parents.root` → `backendError`；`readVolumeMeta` 找到 **且** `volumeDirExists` 为 true 才算存在，否则 `NotFound`；读取出错 → `backendError`。
static id 的行为不变（只查配置）。仍然不持锁。

### 5. `driver.go` / `server.go`
- `New`：controller 模式创建 `controllerService{driver, locks: newInflight(), parents: newParentMounts(newMounter(opts.MountLogDir), opts.ControllerMountDir), now: time.Now}`。

## 测试（表驱动，断言行为）
测试用 `fakeMounter`（`node_test.go`）替换 `parents.mounter`，`parents.dir` 用 `t.TempDir()`；fake 的 "挂载" 不做任何事，因此 root 就是临时目录，
目录与元数据操作是真实的文件系统操作。需要按路径切换挂载状态时用 `mountStateOf`，需要新计数器（如 Detach 次数）可以加到 `fakeMounter`。
1. `parentmount_test.go`：NotMounted → 建目录、挂载一次（断言 Spec 的 Servers/Volume 与路径）、返回的 root 指向该目录；Mounted 且有缓存 →
   不挂载、返回同一个 `*os.Root`；Mounted 无缓存 → 不挂载、打开 root；Corrupted → 先 Detach 再挂载，旧 root 已关闭（在其上操作得到 `os.ErrClosed`）；
   Mismatch → 错误，不挂载、不 Detach、不卸载；VolumeMountState 出错、挂载出错 → 错误且不缓存（下次调用会重试挂载）；另一个 goroutine
   持有 `sem` 时，已取消的 ctx 立即返回 ctx 错误；两个 cluster/父卷得到不同路径；`close` 对每个挂载过的路径恰好 Unmount 一次、关闭 root、
   重复调用 no-op；非法 clusterID/volume（`..`、`a/b`）→ 错误且不调用 mounter。
2. `subdirvolume_test.go`：元数据往返；`found=false`；未知字段、末尾多余内容、version 2、非法 onDelete、负容量、超大文件、非 JSON → 错误；

  retain 删除目录；delete 不删元数据；目录处理失败仍删除元数据；DeleteVolume 对未配置 cluster 返回 OK；static 卷的 DeleteVolume 调用 mounter；
  Corrupted 时不 Detach；重挂时不关闭旧 root；Mismatch 时卸载或挂载；挂载失败后缓存 root；`close` 不卸载；VVC 不查目录存在；
  不声明 `CREATE_DELETE_VOLUME`；Serve 返回不调用 `close`。
