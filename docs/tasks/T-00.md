## 交付物

### 1. `.github/workflows/ci.yml`
- 触发：`push` 到 main、所有 `pull_request`。
- `permissions: contents: read`（最小权限）；`concurrency` 按 ref 取消旧运行。
- jobs：
  - `lint`：golangci-lint-action。
  - `test`：`go test -race -coverprofile=coverage.out ./...`，上传 coverage 为 artifact 不需要；在日志中打印 `go tool cover -func` 的总计行。
  - `verify`：检查 `gofmt -l .` 为空；`go mod tidy` 后 `git diff --exit-code go.mod go.sum`。
  - `build`：`make build`，运行 `./bin/glusterfs-csi --version`。
  - `dco`：仅 `pull_request` 触发。用内联 shell 检查 `${{ github.event.pull_request.base.sha }}..${{ github.event.pull_request.head.sha }}` 范围内每个非 merge 提交都含 `Signed-off-by:` 行，缺失时列出提交并失败。checkout 需 `fetch-depth: 0`。不得使用第三方 DCO action。

### 2. `.github/workflows/image.yml`
- 触发：`push` 到 main、`push` tag `v*`、`pull_request`。
- PR：多架构构建（linux/amd64,linux/arm64）**不推送**、不登录。
- main / tag：登录 ghcr.io（`GITHUB_TOKEN`），`permissions: contents: read, packages: write`，推送。
- metadata-action 标签规则：main → `main` 与 `sha-<short>`；tag → `{{version}}`、`{{major}}.{{minor}}`。
- 构建参数传入 `VERSION`、`GIT_COMMIT`、`BUILD_DATE`（Dockerfile 已有这些 ARG）。不要传 `GO_IMAGE`/`BASE_IMAGE`，CI 使用 Dockerfile 默认的官方镜像。
- 使用 GitHub Actions 缓存（`cache-from/to: type=gha`）。

### 3. `.github/dependabot.yml`
`gomod`、`github-actions`、`docker` 三个生态，每周一次；gomod 中将 `k8s.io/*` 归为一组，`google.golang.org/*` 归为一组。
